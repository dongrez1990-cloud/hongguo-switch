## 二、查到的隐患：轮询线程与 `Impl` 的竞态

```cpp
static void pollLoop(Impl* impl) {  while (impl->alive) { drainMpvEvents(impl); sleep(500ms); ... } }
...
PlayerView::~PlayerView() { impl->alive = false;  ... delete impl; }   // ← 没有等线程退出
```

析构把 `impl` **立刻 delete** ✓，而轮询线程最多还要睡 **500 ms** 才醒 ✓ → 醒来后读的是
**已释放内存**里的 `impl->alive` ✗ —— 更糟的是它会去 **drain 一个已经被销毁的 mpv 句柄** ✗✗
（`mpv_terminate_destroy` 就在 `delete impl` 之前两行 ✓）。这是与三次崩溃**同一类**的 use-after-free，
只是发生在**退出播放**而不是使用中。

**修法两处**：

1. **睡眠切成十片**（10 × 50 ms ✓）：线程对 `alive` 的响应从 500 ms 变成 50 ms，而**轮询节奏不变**
   （每 10 片做一次 drain ✓）；
2. 析构里在 `alive = false` 之后 **等 `pollers` 计数归零**（最多 2 s，每 10 ms 看一次 ✓），**然后**才
   释放 renderCtx / mpv / 纹理 / 像素 / `Impl` ✓ —— 并**把等待毫秒数打进日志**（"线程没停"这种事不该靠以后推断 ✓）：

```
SHUTDOWN: waited 10 ms for the poller (pollers left: 0) [build75]
```

> 没有直接把 500 ms 原样等掉，是因为那会让**每次退出播放**都卡半秒 —— 分开的睡眠让两个目标都满足。
