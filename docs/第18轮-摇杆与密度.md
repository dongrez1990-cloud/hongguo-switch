# 第 18 轮：摇杆四向、首页密度、卡片滚动

**用户第三轮反馈**：

> 「第一张图的主界面还是只有 3 个显示出来，其他的都被挡住了，把它变成浏览器的那种可以下滑的。
> 第二个选集数界面有可以下滑的了，但是摇杆和 D Pad 都只能左右移动，一集一集的移动，
> 把它做成适合现代的操作。」

两张照片给的线索很关键：**选集网格能滚、首页网格不能滚**，而它们是同一套 `ScrollingFrame`、
同样的 `followFocus`。

---

## 一、首页"只有 3 个"的真正原因：**卡片比屏幕还高**

上一轮我把 `home.cellW` 设成 380，算出的是：

```
380 -> 3 列，卡片 400 x 656 逻辑像素      ← 656 已经接近整个屏幕高度
```

**一张卡片就把屏幕占满了**，所以"能滚动"在物理上没有意义 ——
`contentH - viewH` 几乎没有余量，滚也滚不出东西。这解释了为什么选集网格（按钮只有 56 高）
能滚、而首页不能：**不是滚动坏了，是首页根本没有可滚的空间。**

**改回 240**，实测：

```
240 -> 5 列，卡片 234 x 406，一行 424 高
       屏幕能放下将近两行，第三行露头        ← 这才是"网格还能继续"的样子
```

这个密度也接近 wiliwili 参考截图里的观感（四列、能看到两行多）。
`home.cellW` 仍然可以覆盖，X 键仍然在小窗/大窗之间切（240 的 55% = 9 列）。

## 二、摇杆：从"只有左右"到"四向 + 长按连发"

**根因有两层，而且是两件不同的事**：

### 第一层：网格的移动方向本来就不对

上一轮我把网格的 `getNextFocus` 重载成"按行列走"，但**这个重载几乎不会被调用**：
`Actor::moveSelection` 走的是 `getCurrentFocus()->getNextFocus()`，而**焦点通常在卡片上**，
卡片的 `getNextFocus` 直接交给父节点 —— 于是要不要问网格，取决于 Box 的 axis 判断。

**现在的做法是把移动放在网格自己手里**：`moveFocus(direction, currentView)` 直接算目标格子
（左右 = 列 ±1，上下 = 相邻行的最近列），移动焦点**并同时滚动**。
`getNextFocus` 重载保留但一律返回 `nullptr`，它只是让框架的遍历到此为止。

**为什么"上下 = 换一行"是"现代操作"的关键**：222 集、每行 8 个，
按一下下从第 3 集跳到第 11 集 —— 而不是第 4 集。**一集一集走 222 次不是操作，是惩罚。**

### 第二层：摇杆从来就没有被翻译成导航

我把输入映射表读出来了（`switch_input.cpp`）：完整手柄下 `BUTTON_NAV_*` 映射的是
`HidNpadButton_AnyUp/Right/Down/Left`，而 libnx 的定义（`hid.h:294`）说
`AnyUp = Up | StickLUp | StickRUp` —— **也就是"包含 D-Pad 和摇杆"**。
所以按文档摇杆本该和 D-Pad 一样，但真机行为对不上，而**我在构建机上无法判定是哪一环断了**。

**所以我不再依赖这个假设**：直接读**摇杆的模拟轴**（`axes[LEFT_X/LEFT_Y]`，
`switch_input.cpp:251` 已经在填），自己合成四个方向 —— 用哪个手柄摇杆都能用（哪个推得远用哪个）。

**加了长按连发**：400 ms 延迟后每 120 ms 走一步。**没有连发的摇杆**在 222 集的页面上
意味着"按住不动" —— 那是可用性最差的做法。延迟是为了**轻推一下只走一格**（没有它，
最短的一次触碰会滑过好几行，用户没法瞄准）。

**为什么不走框架的导航入口**：`Application::navigate()` 和 `handleAction()` **都是私有的**
（`application.hpp`：`private:` 从 361 行开始，`navigate` 在 431、`handleAction` 在 442），
而 `upstream/` 在这个项目里是**只读参照树**、至今没有任何一处被改过。
所以轮询和移动只能各自在我自己的代码里，而它们本来就已经在同一个地方相遇：**网格的每帧钩子**
（`draw()`）—— 网格拥有自己的几何，所以"这个方向推一下是什么意思"本来就该由网格回答。

**这一条要诚实说明**：它不经过 `handleAction`，所以**如果某个屏幕把方向键绑成了自定义动作**，
那个动作在摇杆上不会触发。**这个项目里没有任何屏幕这么做**（播放器绑的是 LB/RB/Y/X/START，
都不是方向），所以两个输入在这里等价。高亮抖动和音效也不会触发（纯观感）。
