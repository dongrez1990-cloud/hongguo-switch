## 二、这一版补上的是**点屏幕** ✓（这也是本 fork 里最难的一环）

| 走过的死路 | 结论 |
|---|---|
| `Application::currentTouchState` | **私有** ✗ |
| `InputManager::updateTouchStates` | 它是**喂**数据给框架的 ✗，不是读接口 |
| `View` 上的触摸钩子 | 不存在 ✗ |

**正门** ✓：`brls::GestureRecognizer` 的子类 —— 框架会把 **`TouchState`（含坐标 ✓）** 交给它的
`recognitionLoop()` ✓✓。所以：

```cpp
class HgTouchLayer : public brls::GestureRecognizer {
    brls::GestureState recognitionLoop(TouchState touch, …) override {
        if (touch.phase == TouchPhase::START) view->onTouchAt(x, y);
        return GestureState::FAILED;   // 只做"传递坐标"，不跟框架抢手势 ✓
    }
};
```

而**命中区早就在绘制时记录好了** ✓（`chipHit` / `menuHit` / `volumeHit` ✓）—— 之前它们**没有消费者** ✓，
这一版正是为它们写的消费者 ✓✓。

### 点屏幕的三种行为（按优先级 ✓）

| 情况 | 行为 |
|---|---|
| **上拉菜单开着** | 点菜单行 → 选中并应用 ✓；点音量条 → **拖动** ✓；点别处 → 关掉菜单 ✓ |
| **控制条开着** | 点某个格子 → 选中并执行 ✓（播放/音量/倍速/缩放/清晰度/设置 ✓） |
| **点画面其它地方** | **呼出 / 收起 UI** ✓✓（收起后由空闲计时器接管 ✓） |

日志会逐次记录 ✓：`PLAYER: touch -- …` ✓（例如 `touch on the picture -> showing the UI` ✓）。
