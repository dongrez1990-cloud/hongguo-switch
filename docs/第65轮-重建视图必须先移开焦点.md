# 第 65 轮：审计查到的框架事实 —— 重建视图的人必须先移开焦点（build65）

这一轮审计的是一类**系统性问题**：我写的几个界面都会"重建视图树"（搜索出结果、收藏切标签、分类翻页、
主页刷新），而**焦点可能正落在被重建掉的卡片上**。查 borealis 的删除路径后，得到一个必须写进规范的结论。

---

## 一、框架事实（`application.cpp:209-224`，实测读源码）

```cpp
// Free views deletion pool. A view deletion might inserts other views to deletionPool
for (auto view : Application::deletionPool) {
    if (!view->isPtrLocked()) delete view;
    ...
}
Application::deletionPool = undeletedViews;
```

**它删除视图，但不清 `Application::currentFocus`。** 也就是说：

> **谁销毁视图，谁就必须先把焦点移开。** 否则框架手里握着一个**悬空指针**，
> 下一次按键/绘制就会走到已释放内存上。

这不是理论问题：本项目的 `View::ptrLock` 机制正是为了让"回调还在用、视图已被排队删除"这件事安全
（图片加载器那次堆损坏就是它救的）—— 而**焦点没有任何这类保护**。

## 二、逐条查我自己的重建路径

| 界面 | 重建点 | 之后是否移动焦点 | 结论 |
|---|---|---|---|
| 主页 | `applyHome` → `setRows` | **是**（紧跟着 `giveFocus(grid)`） | ✅ 安全 |
| 搜索 | `applyResults` → `setPosterGridRows` | **是**（结果到达后聚焦网格，且是有意的） | ✅ 安全 |
| 分类 | 第 1 页 `setPosterGridRows` + `giveFocus`；后续页是**追加**（不销毁） | **是** | ✅ 安全 |
| 详情 | `setEpisodes` → 紧跟 `giveFocus(episodeGrid)` | **是** | ✅ 安全 |
| **收藏/历史** | `applyEntries` → `setPosterGridRows` | **否** ✗ | ✗ **修** |

**为什么能真的发生**：用**触屏点标签**时焦点不会先移到标签上（用手柄按才会），
所以点标签那一刻焦点可能正在一张**海报**上 —— 而重建会把那张海报销毁 ✓✓。

## 三、修法：只在该移的时候移（不抢焦点）

```cpp
const bool hadGridFocus = focusIsInside(this->grid);
setPosterGridRows(this->grid, rows);
if (hadGridFocus) brls::Application::giveFocus(this->grid);
```

`focusIsInside()` 从 `getCurrentFocus()` 沿 `getParent()` 往上走（几行）✓。
**问"焦点原本在不在网格里"而不是"直接给网格焦点"**，是为了**不抢焦点**：
手柄用户点标签时焦点在标签上（不该被搬走），触屏用户点标签时焦点在卡片上（那张卡片马上要被删，必须搬）✓。

## 五、请真机确认

1. 进 **收藏/历史页** → **用手指点**另一个标签（不要在卡片上停住焦点再用手柄按）→ 列表切换后
   **方向键与 A 应当立刻能用**（以前可能因为焦点被悬空而没反应甚至崩）。
2. 若日志里出现 `LIBRARY: the focus was inside the grid, which the rebuild destroys -- moved back into it`
   就说明这次走到的正是那条路径（这行日志本身就是"路径被触发过"的证据）。
3. 回归：主页刷新（LB）、搜索出结果、分类翻页、详情页选集后的方向键都应正常。
