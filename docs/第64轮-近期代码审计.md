真机日志没变（还是 `build39`，31358→31354 字节不变），所以 I2/I3 的测量拿不到。
这一轮改成**审计我自己最近写的代码**：上一轮的"过期说法清扫"抓到过一条用户可见的 bug，值得再来一次。

## 一、找到的 bug：设置面板开着时，A 与 B 都错了

`build47` 我写了 `PlayerView::settingsIsOpen()`，**但它从来没有被调用过**。而 A/B 两个注册动作只守了画面菜单：

```cpp
if (view->menuIsOpen()) { ... return false; }     // 只守菜单
```

**同时**，`tickSettings`（每帧轮询）在 A 或 B 按下时会关掉设置面板 —— 于是**同一次按键被两条路径处理**：

| 键 | 轮询做的 | 注册动作随后做的 | 用户看到的 |
|---|---|---|---|
| **A** | 关掉设置面板 | `activateControl()`（控制条还在）→ 若选中项是"设置"→ **又把面板打开** | **按 A 像什么都没发生** ✗ |
| **B** | 关掉设置面板 | 落到 `popActivity` → **退出播放** | **只想关面板，结果退出了播放** ✗ |

（这正是本项目反复出现的那一类 bug：**一个界面两条输入路径，谁都不知道对方刚做了什么** ✓ 方向键当初就是这么错的 ✓。）

**修法**：两个守卫都加上 `view->settingsIsOpen()`（与 `menuIsOpen()` 同一形状 ✓），
于是轮询负责"关面板"、注册动作只报告并返回 false ✓，`settingsIsOpen()` 这个接口终于有了调用者 ✓。

## 二、审计过、**不是** bug 的一项（记下来免得以后有人"修"它）

**分类页"滚到底自动取下一页"的回调捕获了 `this`**，而活动销毁后视图可能还活在 borealis 的延迟删除队列里。
查了触发路径：它**只从该视图自己的 `draw()` 触发**，而绘制是从**当前活动**的视图树走的 ——
已弹出的活动的视图不在那棵树里，**不会再被绘制**，所以回调不可能在活动死后被调用 ✓。

不过我还是**加了一行**在析构里把它断开（`setPosterGridNearBottom(grid, nullptr)`）：
代价是一次空指针判断，换来的是这条生命期规矩**由构造保证**而不是"仅靠推理成立" ——
播放器里那句 `clearMenuOverlayCallback()` 就是为同样的理由存在的 ✓。
