## 一、代码里到底发生了什么

`retryCoverIfMissing()`（每个封面格子的"再问一次"）原来的判定是：

```cpp
if (state == HG_IMG_INSTALLED || state == HG_IMG_FAILED) return;   // 只有"已装好/确定失败"才不问
```

而 `HG_IMG_PENDING` 这一个状态**同时表示两件事** ✗：

| 它被用来表示 | 实际情况 |
|---|---|
| "loader 拒绝了我（名额满/节流）" | 应该**再问** ✓ |
| "**已经有一个下载在跑**" | 应该**别再问** ✗✗ |

于是**每一轮重试（400 ms）都会给"正在下载中的格子"再发一次请求** ✓ →
**同一个格子可能有多个下载在飞** ✗ → 它们**先后回来** ✓ →
而每一次回来都要执行 **LOAD** ✓：`nvgCreateImageMem` → `innerSetImage` ✓
→ 这一步**建一块新纹理 + 删掉旧纹理** ✓ ——
而**deko3d 不一定在同一帧就把旧纹理的内存还回去** ✗
→ **新纹理建立时，旧的那块还没回收** ✓✓ = **你说的"还没显示就卸除负载、装载又过来"** ✓✓✓。

一个格子同时有两三个下载 ✓、每次回来都做一次"建+删" ✓、滑动的瞬间多个格子同时这样 ✓
→ 这就是崩溃 ✓。

## 二、修法：把"在飞"从 PENDING 里拆出来

| 状态 | 含义 |
|---|---|
| `HG_IMG_PENDING = 0` | **没有下载在跑**，可以再问 ✓ |
| `HG_IMG_INSTALLED = 1` | 已装好 ✓ |
| `HG_IMG_FAILED = 2` | 确定失败 ✓ |
| **`HG_IMG_IN_FLIGHT = 3`** | **正在下载**：**别再问** ✓✓ |

并且**每条退出路径都写状态** ✓（我专门核对过 ✓，避免"卡在在飞、永远不再取" ✗）：

| 行 | 状态 | 时机 |
|---|---|---|
| 185 | PENDING | 进入（含被拒绝 ✓） |
| **279** | **IN_FLIGHT** | **抓取真正开始** ✓ |
| 350 / 359 / 368 | FAILED | 确定失败 ✓ |
| **403** | **PENDING** | **响应被丢弃**（URL 已变 ✓）← 本轮新增 ✓ |
| 421 | INSTALLED | 装好 ✓ |
| **437** | **PENDING** | **没有工作线程** ✓ ← 本轮新增 ✓ |

→ 现在**每个格子同时只有一个下载** ✓，**装载只发生一次** ✓ → 你说的那个竞态**不存在了** ✓。
