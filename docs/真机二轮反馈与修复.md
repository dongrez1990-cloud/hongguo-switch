## 一、选集界面：只有左右能用，上下没用

**报告**：「在选集数界面，只有左右，上下用不了」。

**第 14 轮把轴改成 `Axis::ROW` 之后的必然结果，而且我上一轮就该想到**：
`Box::getNextFocus`**只让两个方向遍历子节点**，另外两个交给父容器：

```cpp
if ((axis == ROW    && direction != LEFT && direction != RIGHT) ||
    (axis == COLUMN && direction != UP   && direction != DOWN))
    -> 交给父节点
```

换成 ROW 之后，**左右**走子节点（列之间），**上下**交给 `ScrollingFrame` ——
而那个滚动器**自己没有可聚焦的子节点**可以交给焦点搜索，于是上下彻底没反应。
**换成 COLUMN 只是把坏的轴调个方向**，两个方向里总有一对坏。

**真正的修法：自己做空间导航。** 两个网格现在都重载 `getNextFocus`，
用 `hg_grid_layout` **已经算出来**的 `row` / `column`：

- **左右**：同一行、列 ±1；
- **上下**：上一行 / 下一行的**最近一列**（同一列优先）；
- 一行末尾没牌时退到该行最近的一张，**上下不会走进死胡同**；
- 上下跨过分区标题时跳过它（标题不可聚焦）。

不新增任何算术 —— 那些坐标就是卡片被画在的位置。

## 二、预览界面还是"一排"

**报告**：「预览界面还是一排」。

按默认值算是：`home.cellW` 原本 **200** → 720p 下 **6 列**，一个分区 9 张牌刚好排成一行多一点，
整个屏幕读起来像"一条带子"。

**改成 380** → 720p 下 **3 列**，每张卡 **400×656** 逻辑像素（原来 192 宽），
一个分区占 5 行。X 键的小窗模式在 380/55% 下是 **5 列**。

这一条**不确定是否符合你的原意**：如果你是想要"**只有两排**"（每排 2 张、共 4 张一屏），
那要的是另一个数字 —— `home.cellW=620` 左右。现在先用 380，你觉得还不够大就调 cfg，
一行不用重编译。

## 三、首页封面只到 6 张 —— 我上一轮的"重试"是**假的**

第 14 轮加了每 400 ms 的重试，我以为修好了。**日志说没有**：

```
HOMEGRID: cover retry pass 1 (36 cells asked; …)
IMG: 6 fetches already in flight (image.threads=6) -- skipping '…f3c21846…'
IMG: 6 fetches already in flight (image.threads=6) -- skipping '…3f72fc8d…'
IMG: 6 fetches already in flight (image.threads=6) -- skipping '…65a4cd56…'
HOMEGRID: cover retry pass 2 (36 cells asked; …)      ← 同样的三个 URL
```

**同样的三个 URL 在每一次重试里都被拒绝**，一分钟都没变。根因是**我把
"发起了取图" 当成了 "这张卡有图了"**：

```cpp
if (hg::loadImageAsync(cover, s.cover, &slot, …)) hasImage = true;   // 错
```

`loadImageAsync` 的返回值只表示**这次请求开始了**。一张卡如果取图**失败**了
（传输错、状态码错、空 body），`hasImage` 已经是 true，**重试永远不会再发生**，
它就永远停在占位图上。这正是"有些封面永远不出来"的样子。

**修法**：`loadImageAsync` 新增一个 `std::atomic<int>* settled` 出参 ——
**每次尝试都先清零，只有在主线程真正装好纹理的那一刻才置 1**。
格子只在 `settled == 1` 时才算"有图"，于是**失败的格子保持可重试**。

同时把 `image.threads` 默认值从 **6 提到 10**：一次布局有 36 个格子同时要图，
6 个在飞意味着另外 30 个每一轮都被拒。实测单张最坏 1.5 MiB，10 个在飞最多约 15 MiB，
而常见情况只有几百 KiB —— 仍然是有界的。

## 四、选集界面 B 键退不回去

**报告**：「在选集数的界面不能退到预览界面，在播放界面可以推到选集数界面」。

**borealis 根本不为 B 注册任何默认动作** —— 这一点第 9 轮审查时就查过、也写在代码注释里：
整个库里只有 `dialog.cpp` 有两处 B 动作。**所以想用 B 退出的屏幕必须自己注册**，
而 `DetailActivity` 从来没注册过。

它以前"看起来能用"是因为焦点还在外层视图上；**换成网格之后焦点进到了格子里面**，
B 就没有任何处理者了。

**修法**：`DetailActivity::onContentAvailable()` 显式注册 B（注册在**持有焦点的那个视图**上，
因为 `handleAction` 是从焦点视图沿父链往上找的）。

## 五、中英文切换（新需求，已做）

**报告**：「后面设置里面做一个中英文切换吧」。

新增 `hg_lang`：**32 项主机测试**的字符串表 + 切换函数。

- **默认中文**（你要求的那句"界面默认语言中文"直接写进默认值）；
- `language=en` 切英文；**拼错不是错误** —— 回退到默认，界面照常可读；
- 设置界面 **Appearance 标签页**新增 Language 行（`zh` / `en`），需要重启生效；
- 已接入：**设置界面的全部标签名**、**播放器画面菜单**（标题 + 底部提示行）、
  启动时的语言日志行。

**关于中文怎么存进"纯 ASCII 源码"**：这个项目的构建机是 GBK/936，
非 ASCII 源码会以乱码进编译器（已经踩过三次：注释里的中文、字符串字面量里的中文、
一个全角括号）。所以中文**全部写成 `\xNN` 字节转义**，是纯 ASCII 源码，
靠 C 的字符串拼接规则连成一个字符串。

**这个做法自己就有一个坑，而且测试当场抓到**：`\x` 转义是**贪婪**的，
写表的时候我把一个 `\xE4` 打成了 `\xxE4`。`hg_lang_test` 因此**逐个条目校验 UTF-8 合法性**
—— 一个字节错就是控制台上一个乱码方块，而编译器不会报任何东西。

**还有一处更实在的**：`hg_lang_name()` 第一版写的是
`TABLE[ZH + (lang==EN ? 1 : 0)].en` —— 读的是中文那一行的**英文列**，
所以问"中文叫什么"它答 "Chinese"。测试（"Chinese is named in Chinese"）抓到了，
改成读该行自己的列。

## 七、还没做的：选集分页

**报告**：「如果集数比较多，可以做一个 1 至 20、21 至 40 这种缩放集合」。

**没做，因为想先确认一件事**：上面第一条修好之后，D-Pad 能在格子里四向移动了，
"集数多难找" 可能会明显改善 —— 而分页会**把 222 集切成 12 页**，
每次翻页要按好几次键，未必比现在好。

**如果你想做**，我倾向这样做（等你确认）：在选集网格**上面**加一行**区间选择**
（`1-20 / 21-40 / …`），选中后下面的网格只显示那一段。这样"翻页"是一次按键，
而不是滚十几行。**你上机试过四向导航之后再决定要不要加。**
