# 第 102 轮：滑动窗口（"框框"）＋ 被别的界面盖住时全部清除（build102）

你的描述我按字面实现了 ✓：**一个比屏幕大的框 ✓，下面的内容不停进来、上面的不停出去 ✓，往上也一样 ✓。**

---

## 一、框框的具体尺寸（用你的数字反推）

| 参数 | 值 | 依据 |
|---|---|---|
| **预加载（往下）** | **4 排** ✓ | 你的原话："检测到在其中某一排就预加载**下面的四排**" ✓ |
| **往上保留** | **1 排** | 滑回去时上面那排已经在了 ✓ |
| **卸载线（往上）** | **16 排** | 你的数字 **168 格 = 21 排 × 8** ✓ → 窗口 5 排 + 上面 16 排 ✓ |

→ 框里始终保留最多约 **21 排（168 格）** ✓，超过就**从最上面开始卸负载** ✓（"反正看不到上面的内容" ✓）。

## 二、**一排一排地走**（修掉"跳排"）

之前是"**把所有格子都问一遍**" ✗ → 加载器的 8 个名额被"循环先扫到的 8 个格子"占满 ✓
→ 所以会出现**空一排、先出下面两排** ✓（你观察到的现象 ✓）。

现在改成**有序走** ✓：

```
1. 先算出"视口现在在第几排"（用绝对坐标，跟着滚动走 ✓）
2. 窗口 = [该排 - 1, 该排 + 4]
3. 按排**从前往后**走：找到第一排"还有格子没搞定"的
4. 只请求这一排（8 个格子 = 8 个名额，正好一排 ✓），然后**本次结束** ✓
5. 下一轮（400 ms 后）再走下一排 ✓
```

→ **一排没走完，不会碰下一排** ✓✓（这正是你要的 ✓）。
"搞定"的判定包含三种情况 ✓：**已装好 ✓ / 确定失败 ✓（不阻塞整排 ✓）/ 正在下载中 ✓（不重复请求 ✓）**。

## 三、**被别的界面盖住 → 全部清除**（新加 ✓）

> "然后再进入播放界面或者选集界面、其他界面的时候，这个界面就全部清除。"

之前没做这条 ✓ —— 而它其实是内存故事的另一半 ✓：
**主页在播放器压上来时并不会被销毁** ✗（它留在活动栈里 ✓，168 张封面仍在内存里 ✗），
而播放器要分配 **3 MB 播放表面 + mpv 自己的缓冲** ✗ → 压力叠加 ✓✓。

**实现**：每帧检查活动栈 ✓ ——

- 栈里**大于 1 个**（说明有界面盖在自己上面）→ **释放全部已加载封面** ✓，日志：`all 87 loaded covers were released` ✓；
- 回到只有自己 → 什么都不用做 ✓：**每个被释放的格子都已标记"再给我一张"** ✓，
  于是**有序走**会自动把它们**一排一排**重新取回来 ✓✓（正是你要的"回来时也用同一套流程预加载" ✓）。
