# 第 44 轮：音量 / 倍速 / 缩放（控制条上的三个值）（build44）

**A3（音量）、A5（倍速）、A6（缩放）** —— 这三个值在这之前**根本不存在**：播放器只有画面菜单里那五个
画面参数（亮度/对比度/饱和度/gamma/hue）+ 清晰度/比例/镜像。这一轮把它们做出来，放在控制条上。

---

## 一、为什么它们不在画面菜单里

X 菜单管的是**画面**（亮度/对比度/清晰度/比例）；音量/倍速/缩放是**播放控制**，用户给的对照图也把它们
放在底下那条 bar 的右下角。所以它们有自己的一小组数值模型，不塞进 X 菜单。

## 二、数值模型放 C 层，带 41 项主机测试（`hg_ctl.h/.c`）

三个值每一个都能**悄悄地错**，所以每一个都是纯函数 + 测试：

| 值 | 规则 | 为什么必须测 |
|---|---|---|
| **音量** | 0..100，步长 5，**两端夹紧** | 一个会"回绕"的音量（100 → 0）是惊吓，不是功能 |
| **倍速** | **阶梯** 0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 1.75 / 2.0（默认 1.0） | 必须能**精确回到 1.0x**；连续调节被碰过之后就很难回到原值 |
| **缩放** | 阶梯 1.0 / 1.25 / 1.5 / 2.0，**标签是倍数、送给 mpv 的是 log2** | mpv 的 `video-zoom` 定义是"按 2^值 缩放"：倍数 2.0 要发 **1.0** 而不是 2.0 —— 发错就是画面被多放大一倍，而标签还在说 1x |

新增 17 套测试的第 17 套（`hg_ctl_test.c`，41 项），并接进 `run.ps1` 的汇总行与失败判定。

## 三、控制条上的操作方式（不改任何已确认可用的按键）

| 键 | 行为 |
|---|---|
| **A** | 控制条不在 → 呼出；在 → 播放/暂停（同 build43） |
| **上/下** | **在控制条的项之间移动选中**（播放按钮 → 进度 → 音量 → 倍速 → 缩放，首尾回绕） |
| **左/右（选中"进度"时）** | **和以前完全一样**：拖动定位 / 长按加速（一行代码都没改） |
| **左/右（选中音量/倍速/缩放时）** | 调整该值（步进） |
| 任何按键 | 重新计时（4 秒无输入才自动隐藏） |

**关键点**：只有当选中项**不是进度**时，左右才交给控制条。所以"拖动定位"这条你已经确认可用的功能
**不会**被新功能抢走；要调音量就按一下下键，要回去拖动就再按回来。这是这一轮唯一需要判断的设计，
写在代码注释里了。

## 四、两次"读回"（本项目最常重复的失败模式）

写 mpv 属性**每次都读回并打日志**，因为"被接受但什么也没发生"和成功长得一模一样：

```
PLAYER: volume = 80 -> set rc=0, read back 80 (rc=0)
PLAYER: speed = 1.25x -> set rc=0, read back 1.25x (rc=0)
PLAYER: zoom = 1.25x (video-zoom 0.3219) -> set rc=0, read back 0.3219 (rc=0)
```

cfg 种子：`player.volume` / `player.speed` / `player.zoom`（值不合法时由 `hg_ctl` 夹紧并记日志），
新增 `hg::cfgIntOr` / `cfgDoubleOr` 两个读取助手（解析失败会记日志，而不是当没写）。

## 六、请真机确认

1. 播放中按 A → 控制条出现：左边播放/暂停按钮，中间进度+时钟，**右边三个小方块：`100%`、`1.0x`、`1x`**。
2. **按上/下** → 选中框在这几项之间移动（进度 → 音量 → 倍速 → 缩放 → 回到播放）。
3. **选中 `100%` 时按左右** → 音量变化（每一步 5，日志有 `volume = 105`？不会，会夹在 100）；
   **选中 `1.0x`** → 倍速变 1.25x/0.75x…；**选中 `1x`** → 缩放变 1.25x/1.5x/2x（画面应变大）。
4. **选中"进度"时左右** → 拖动定位，行为与之前**完全一致**。
5. 不动 4 秒 → 控制条消失；再按 A 回来。
