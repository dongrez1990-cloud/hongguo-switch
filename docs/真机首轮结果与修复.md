## 一、D-Pad 方向反了 —— 根因在**一行**，而它解释了两张图

**用户报告**：「图片排列是左右排列，但是按键还是用 D Pad 的上下操作」。

**根因**：两个网格的内容盒都建成了 `brls::Axis::COLUMN`：

```cpp
contentBox->setAxis(brls::Axis::COLUMN);   // home_activity.cpp / detail_activity.cpp
```

而 borealis 的 `Box::getNextFocus` **不是空间搜索，是按插入顺序走的**，它的第一句就是：

```cpp
if ((axis == ROW    && direction != LEFT && direction != RIGHT) ||
    (axis == COLUMN && direction != UP   && direction != DOWN))
    -> 把方向交给父节点
```

**轴决定"哪个方向来遍历这些子节点"，另一个方向直接交给父容器。**

所以 COLUMN 的效果正是用户看到的：
- **UP/DOWN** 去遍历我的子节点 —— 而子节点是**按阅读顺序**存的，于是"上下"变成沿着一行走；
- **LEFT/RIGHT** 交给了 `ScrollingFrame`，而它是**竖向滚动器**，对这个方向答不上来 → 什么都不动。

**修法**：内容盒改成 `Axis::ROW`。子节点本来就是阅读顺序（索引向右增、换行向下），
所以 ROW 正是"遍历它们"的那个轴：**左右在列之间移动，上下离开这个盒子交给框架滚动**。
视觉布局**完全不受影响** —— 每个子节点都是绝对定位、不在 flex 流里，轴管不到它们的位置。

**一处修两个屏幕**：首页网格与详情页选集网格是同一个 bug、同一个修法。

## 二、首页只有前 6 张封面 —— 是我 `image.threads` 上限的"半成品"

**照片 1** 里只有前 6 张卡有海报，其余 30 张是占位深灰。日志给出了直接原因：

```
IMG: 6 fetches already in flight (image.threads=6) -- skipping 'https://…'
   （连续 4 条，之后还有更多）
HOMEGRID: layout #1 w=1232 large -> 6 columns, cell 192.0x0.0, contentH=3054 (36 cards, 4 headings, focus was item -1)
IMG: installed 76430 bytes …
IMG: installed 168337 bytes …
   （一共只装了 6 张）
```

一次布局把 36 个格子**同时**绑定，而 `loadImageAsync` 对超过 `image.threads` 的请求**直接拒绝**，
**而且没有任何东西会回来重试**。于是 6 张到位，30 张**永远停在占位图上**。
从用户的角度看，这就是"封面坏了"。

**上限本身是对的**（每次取图 = 一个线程 + 最多 1.5 MiB 缓冲）；**缺的是这个想法的后半段：
被拒绝的格子必须回来**。

**修法**：`HomeGridCard::retryCoverIfMissing()` + `HomeGridView::tickCoverRetries()` ——
网格在 `draw()` 里每 400 ms 跑一遍，把还没拿到图的格子重新要一次（已经拿到的格子不再提供重试，
所以屏幕补全后开销归零）。封面会**每 400 ms 到 6 张**，成批补齐而不是永远不来。

顺带说明一个日志细节：`cell 192.0x0.0` 里的 `cellH=0` 是**正确的** ——
那是第 0 行（分区标题）的格子，标题没有海报。

## 三、画面菜单"不知道该怎么操作" —— 面板只说了一半

**用户报告**：「我看到了画面质量的选项，但是我不知道该怎么操作，点 A 键是没反应的」。

**先澄清一个事实**：A 键**是有反应的** —— 两个注册动作有日志：

```
PLAYER: A pressed while the menu is open -> menu closes (not pause)
PLAYER: B pressed while the menu is open -> menu closes (not back)
```

A 和 B 都是**关闭面板**。**用户没找到出口，是因为面板的提示行只说了行内怎么调**：

```
Up/Down row   Left/Right change   A restores all      ← 旧文案
```

一行不透明的浮层**最该说清的永远是"怎么退出去"**。

**修法**：提示行改成把出口放第一位，并说明 A 在这里不是"激活本行"（每一行都是左右改，
没有需要 A 去激活的东西）：

```
B or A closes   -   Up/Down row   -   Left/Right change
```

## 四、选集按钮没有图 —— **上游根本没有**（这次是实测，不是猜）

**照片 2** 里选集按钮只有编号、没有封面。我在动手前先查了数据：

```
app/src/tests/fixtures/detail_router.json 里的键：
  loaderData / seriesDetail / vid_list / series_cover / series_id / series_name / series_intro
```

**详情页载荷里唯一的图片字段是 `series_cover`（剧集封面），`vid_list` 是纯 id 字符串。**
所以"每一集有自己的封面"**上游不提供** —— 这与搜索结果页一样，是**数据没有**，
不是解析器漏了字段。

**所以我不会去编一个映射。** 可行的做法只有两个，都记在这里等选择：

| 做法 | 说明 |
|---|---|
| **用剧集封面做按钮底图** | 数据是真的。需要一个**共享纹理**路径，而 `brls::Image` 会给每一张用自己的 `NVGimage`，76 份下载会撞上同一个 `image.threads` 上限（就是问题二）。**不能简单地每格一张。** |
| **把按钮本身做得更清楚** | 编号 + 更大字号 + 更好的间距，**不依赖任何图片** |

**当前的编译产物已经包含问题一～三的修复**，这一条留待你选。

## 六、这次真机运行证明了什么（值得记下来的部分）
