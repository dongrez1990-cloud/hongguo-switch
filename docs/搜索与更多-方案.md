## 一、搜索页（按 Y 进）——**数据源是搜索页 HTML，不是签名 API**

| 事实 | 出处 |
|---|---|
| `https://hongguoduanju.com/search/<urlencoded 关键词>` → **200，211 KB HTML** | `docs/让程序可用-步骤.md:51` |
| loaderData 的内容键是 **`search_(keyword)/page`**（括号和斜杠就在键名里） | 同上 `:140`；`hg_fixture_test.c:268` 有这条断言 |
| 内容数组是 **`searchList[]`**，**实测 10 项/页，`totalCount: "108"`** | 同上 `:140` |
| 条目顶层字段是 **`name`（标题）+ `keyword`（= series_id）**，不是 `series_name`/`series_id` | 同上 `:143-151` |
| **签名搜索 API 是死的**：200 + `Content-Length: 0`（用参考实现本身复现过） | `probe_search_cursor.mjs`、`probe_sources.mjs`、`hg_request_diag.c` |

**所以**：`hg_api_parse_search()` 解析的是**死掉的签名 API 的形状**（`video_data[]`），
**不能**用来解析搜索页 —— 需要一个新解析器（按 `searchList[]` / `name` / `keyword`），
按 `hg_api_parse_home` 的写法加，并补主机测试（形状不同，这正是这个项目栽过的那类坑）。

**虚拟键盘：用系统键盘，不要自己画。** 这台机器上已经有：
`brls::Application::getImeManager()` → `SwitchPlatform` → `SwitchImeManager`
（`switch_ime.cpp` 用 libnx 的 `swkbd`，`SwkbdType_All`，可设标题/副标题/最大长度/初始文本/禁用键掩码）。
调用形状见 borealis 自己的 `views/cells/cell_input.cpp:30`：

```cpp
brls::Application::getImeManager()->openForText(
    [this](std::string text) { this->runSearch(text); },
    "搜索", "输入剧名", 40, this->lastQuery);
```

系统键盘自带**拼音输入**（用户要的"英语的拼音输入"就是这个：敲拉丁字母、由系统的 IME 出中文）。

**按键改动**：目前 Y = 设置。设置已经在横排栏里有入口，所以 **Y 改成进搜索页**，
与 wiliwili 的按键表一致（`docs/wiliwili按键与触屏规格.md:37`：主页 Y → 搜索页）。

**结果页怎么画**：结果条目就是 `Series`（标题 + 封面 + id），所以可以直接复用
`HomeGridView`（`setRows()` 传一个平铺的行即可），点开进 `DetailActivity` 的现成路径。

## 二、主页"更多"卡片 —— 跳到该分区的列表

| 事实 | 出处 |
|---|---|
| 分类页也是 HTML SSR，内容键 **`category_page`**，数组 **`recommendList[]`（实测 24 项）** | `docs/让程序可用-步骤.md:139` |
| 分类页条目的标题字段是 **`series_name`** | 同上 |
| 首页每张卡片自带 **`category_list`**（归类标签，36/36 都有） | `hg_api.h:81`、`hg_api.c:785-798` |
| `category` 与 `search` 的 loaderData 键名都已实测（`category_layout` / `category_page`） | `hg_api.h:192` |

**还差一步勘察**：分类页 URL 的**参数形式**（哪一个参数选到某个 tier 的 category）。
`hg_api.h:192` 只记了载荷形状，没记 URL 参数；需要像 `dump_all_shapes.mjs` 那样把
`https://hongguoduanju.com/category?...` 的几种形态跑一遍，确认"按 category_list 过滤"用哪个键。

**实现顺序**（与搜索共用同一条 HTML→router→parse 通道）：
1. 分类页 URL + 参数确认（一次探测）；
2. `hg_api_parse_category()`（`recommendList[]` / `series_name`）+ 主机测试；
3. 一个列表页（同样可复用 `HomeGridView`），"更多"卡片把 `sectionTitle` 换成该分区的 category。

> 顺带一条已知的坑：`hg_api_parse_home` 的注释说明**同一部剧会出现在多个分区**（上游行为，刻意保留），
> 所以分类页的数量不能拿"去重后数量"去判断。
