## 一、一个界面、两个标签（`LibraryActivity`）

```
历史记录   我的收藏
显示 12 条
┌────┐ ┌────┐ ┌────┐ ...
│封面│ │封面│ │封面│      卡片标题下面那行：
└────┘ └────┘ └────┘      历史 → 第 3 集   12:34   3 天前
                          收藏 → 3 天前
```

- **两个标签是可聚焦的真按钮**：这个界面的导航交给框架（不像播放器那样轮询手柄），
  所以左右在标签之间走、A 切换 —— 和这个 App 其它界面完全一致。
- **共用主页那套网格**（`makePosterGrid`）：同样的列数、同样的海报、同样的滚动与行步进。
  另写一个网格就是又一份要同步的排版。
- 卡片标题下那行放进 `tags` 字段（网格本来就在标题下面渲染它），**不新增第二种卡片布局**。

## 二、静态数据，不联网

两个列表直接来自 `sdmc:/switch/hongguo-history.txt` 与 `hongguo-fav.txt` ——
**这正是当初把标题和封面写进文件的原因**（`hg_history.h` 在字段旁边就写着这句）：这个界面**完全不发请求**。
时间用文件里记的 `when` 与当前时间算（`hg_fmt_age`），进度用 `hg_fmt_clock`。

## 三、X = 真刷新（D3）

`hg_store` 是**一次进程只读一次盘**的；播放器在后台写历史，所以"我看完一集回来，列表没变"是必然会发生的。
因此 `Store::reloadFromDisk()`：丢掉内存副本、重读两个文件（**走的还是那条加载路径**，
所以"跳过几行坏数据"照样会记日志）。X 键调它，标签切换**不**调它 —— 切标签是重绘，不是读盘。

## 四、侧边栏：从"还没做好"到真实计数

- 两个入口现在**真的打开界面**（`HG_T_FAVORITES` → 收藏标签、`HG_T_HISTORY` → 历史标签；
  用户已经选了哪一个，不该再让他切一次）。
- 副标题从"还没做好"改成 **"显示 N 条"**（收藏/历史各自的条数），配合 `build49` 的"没有内容才灰"。
- 其余栏目的兜底通知（"还没做好"）保留 —— 那是给**确实还没有界面**的入口用的。
