## 一、启动就崩（**最要紧的那条**）：主题应用在视频上下文存在之前

**证据链**：

```
应用日志最后一行：  UI scale: window=0x0 content=0x0 scale=0.000 logical=1280x720   ← 之后进程死亡
崩溃报告：          Result 0x4A8 / Data Abort, Fault Address: 0x0
栈（addr2line）：   brls::SwitchVideoContext::recordStaticCommands()  switch_video.cpp:140
配置：              CFG: option theme = 'dark'
```

**根因**：`hg_boot.cpp` 里我在 `build54` 加的主题块，位置在 **`createWindow` 之前**，而
borealis 的 `SwitchPlatform::setThemeVariant()` **无条件**调用
`this->videoContext->recordStaticCommands()`（`switch_platform.cpp:293-299`）——
那一刻**视频上下文还不存在**，于是解引用空指针，**Fault Address 0x0** ✓✓。

**为什么"几次之后才每次都崩"**：设置界面那一行会把 `theme=dark` **写进 cfg**（持久化），
从那一刻起每次启动都会走到这个空指针 ✓✓ —— 这正是你说的"进不到主页"。

**修法两处**：
1. 主题值**只在这里读**，应用到 **`createWindow` 之后**（那时上下文已存在）；
2. 设置界面的 **Theme 行改成"需要重启"**，并**删掉行处理里的即时应用** ——
   `setThemeVariant` 会重录 **GPU 可能仍在执行**的 deko3d 静态命令列表，这不是行处理器能弄安全的事。
   （"即改即生效"是我上一批自己加的卖点，实测**不成立**，这里如实改回来。）

> 顺带一个行为变化：`theme=auto` 现在真的等于"跟随主机"（以前启动时无条件强制 DARK）✓。

## 二、"更多"和设置界面的闪退：**异步回调踩已释放的界面**（14 处）

**证据**：六份崩溃报告**全部**落在
`brls::Threading::task_loop()` —— 也就是 **`brls::sync(...)` 的任务回调**里。

**根因**（代码就在眼前）：

```cpp
CategoryActivity* self = this;
hg::runDetached([self, slug, page]() {          // 取页面要好几秒
    brls::sync([self, got, r, info, page]() {
        self->applyResults(...);                 // ← 期间按 B 返回 → self 已被销毁
    });
});
```

全项目 **14 处**都是这个形状（分类/详情/主页×2/播放×3/搜索×2 …）✓。
`brls::sync` 只是把 `std::function` 排队，**框架不保证被捕获的对象还活着**；
`View::ptrLock` 保护的是视图，**不保护活动**。

**修法**：新增 `hg_alive.hpp` —— 每个界面持有一个**存活令牌**（`shared_ptr`，回调按值捕获 ✓
所以令牌一定比回调活得久 ✓），回调第一行 `HG_GUARD_ALIVE(alive)`：界面一销毁就 `kill()`，
在飞的 14 个回调全部安全退出 ✓。

## 三、两个进度条（你照片里那条"消不掉"的）

下面那条是**控制条自己**的进度 + "剧名 第 N 集" ✓ —— 屏幕上同时有两份进度和两份集号 ✓。

## 六、补充（第 78 轮）：那两条路径的**因果顺序**

后来在 SD 卡上发现 `hongguo.cfg` 与它**自己留的备份**：

| 文件 | 时间戳 | 主题 |
|---|---|---|
| `hongguo.cfg.bak`（应用改写前自动备份） | 11:29:38 | `theme=light` |
| `hongguo.cfg`（改写后） | 11:29:40 | **`theme=dark`** |

崩溃截图的时刻正是 11:25–11:32 → 于是动作是确定的：**用户把 Theme 从 light 改成 dark，应用写入 cfg，然后崩了**。

这把两条路径的**先后**定死了：

- **第一次崩溃（A）在使用中**：设置行立即调用 `setThemeVariant` → 它会**重录 GPU 可能仍在执行**的
  deko3d 静态命令列表 → 崩（截图里那两次）✓；
- **之后每次启动都崩（B）**：cfg 里已存 `theme=dark`，启动时在 `createWindow` **之前**应用 →
  视频上下文还不存在 → `Fault Address: 0x0` ✓（11:30–11:32 那四次）✓。

**所以"进不到主页"不是一开始就有的，而是 A 的后果** ✓ —— 这也解释了为什么修 A（Theme 行改成"需要重启"）
与修 B（移动 + 空值检查）**两条都必须做** ✓。
