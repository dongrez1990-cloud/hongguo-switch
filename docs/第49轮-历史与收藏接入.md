# 第 49 轮：把历史与收藏接进真实流程（D1）（build49）

**D1**：`hg_history` / `hg_fav`（92 项主机测试）在这之前**全项目没有任何地方调用它们** ——
所以侧边栏的"收藏/历史"一直是灰的，那句"灰是因为数据层没接"的注释也一直是实话。这一轮把它接上。

---

## 一、新模块 `hg_store`：文件位置与**唯一一份内存副本**

`hg_history.c` 只有**格式**（解析/写出/插入/查找/删除），它是刻意不认路径的。缺的是"文件在哪、
什么时候读、内存里那份放在哪" —— 这就是 `hg_store.hpp/.cpp`：

- 文件放在**和 `hongguo.cfg` 同一个目录**：`sdmc:/switch/hongguo-history.txt`、`sdmc:/switch/hongguo-fav.txt`
  （用户想备份/手动删一条，在同一个地方找）。
- **一份副本，一个地方**：主机没有文件监视；写者有播放器（历史）与详情页（收藏），
  读者有主页横排栏（将来还有两个界面）。两份副本就是"我加了收藏但它没出现"的来源。
- 每次改动**立刻落盘**：主机随时可能被电源键结束，只到内存的记录就是丢掉的记录。
- **宁可拒绝也不截断**：字段放不下（512 字节封面 URL / 128 字节标题）时**拒绝写入并记日志** ——
  半截 URL 看起来像成功，比没有记录更糟。
- 读取时跳过多少坏行**会记日志**（丢了一条记录必须能在日志里找到原因）。

## 二、两个真实的写入点

| 写入点 | 行为 |
|---|---|
| **播放器** | 起播时 + **每 15 秒**记一次（`hg_history_put` 按**剧集**归并并置顶，模型自己的规则、也测过）；15 秒是因为电源键随时可能结束会话，位置丢失的代价必须有界 |
| **详情页 Y 键** | 收藏开关。通知说的是**结果**（已加入收藏 / 已取消收藏），因为"开关只有音效"和"按键没反应"分不出来 |

## 三、可见的后果：侧边栏不再一律灰

`setupSidebar` 原来把 `haveWatchlist`/`haveHistory` **硬编码为 false**（注释写着"还没有东西写这两个文件"）。
现在它们来自 `Store::favoritesCount()` / `Store::historyCount()` —— **没有内容才灰**，
正是侧边栏模型当初定的规则。日志写明：

```
STORE: loaded 0 history entries (0 skipped) from sdmc:/switch/hongguo-history.txt
HOME: the bar's content flags -- watchlist=0 (0 entries), history=0 (0 entries)
```

## 四、接口放在自己的头文件里（一个真实的循环）

播放器需要把"播到哪了"交给拥有它的人，而 `player_view.hpp` **已经** include 了 `player_activity.hpp`
（它直接调用活动的 `setMenuOverlay`），所以活动不能反向 include 它。于是把接口放进
`hg_playback_sink.hpp`（`class PlaybackSink`），两边都只 include 它，谁也不用 include 谁。

**顺手记一个链接期的坑**：接口的析构函数若写成头文件里的 `{}`，**没有任何 TU 会为它发出 vtable**，
链接器报 `undefined reference to vtable for hg::PlaybackSink`。所以 `~PlaybackSink()` **声明在头、
定义在 .cpp**（`hg_playback_sink.cpp` 整个文件只为这一行存在）。
