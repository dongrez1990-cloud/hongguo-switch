# 第 76 轮：自查抓到最后一个漏掉的守卫，并把这条规矩变成机械检查（build76）

上一轮我把 33 处异步回调逐个核对过，这一轮做了**反向自查**：不是看"守卫写得对不对"，
而是**数一数"带令牌的回调"和"守卫"的数量是否相等** —— 一数就抓到一个漏网的。

---

## 一、抓到的缺口：**搜索页的结果回调没有守卫**

```cpp
brls::sync([self, alive, got, r, total, upstreamCount, indexSize]() {
    self->applyResults(...);        // ← 缺 HG_GUARD_ALIVE(alive)
});
```

它是**所有回调里最可能"迟到"的一个**：输入关键词、提交、然后在取结果时离开搜索页 ✓✓。
文件里另一处（键盘那处）有守卫 ✓ 所以上一轮"逐个看"的时候不显眼 ✗ —— **计数才让它现形** ✓。

## 二、更重要的是：把这条规矩**变成每次都会跑的检查**

`app/src/tests/run.ps1` 里新增一段**源码不变量检查**：对每个界面文件，数
`brls::sync([self|this|st, alive ...` 的出现次数与 `HG_GUARD_ALIVE` 的出现次数，
**少于就失败并点名** ✓✓ —— 这样"新写一个异步回调忘了守卫"再也不可能悄悄通过 ✓。

**而且我验证了这个检查真的会失败**（变异测试，不是"看起来应该行"）：

| 步骤 | 结果 |
|---|---|
| 故意删掉搜索页那行守卫 | **exit 1**，并打印 `FAIL  search_activity.cpp: 2 guarded callbacks but only 1 HG_GUARD_ALIVE checks` ✓ |
| 恢复守卫 | **exit 0**，`PASS  every brls::sync callback that captures a screen also checks its token` ✓ |

（顺带一个自纠：第一次变异测试**没有触发** ✗ —— 因为我注入变异时那行守卫后面还有一行注释，
替换没匹配上，文件其实没被改 ✓。**一个不会失败的检查比没有检查更糟**，所以我重做了变异才敢说它有效 ✓。）
