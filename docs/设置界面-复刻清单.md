### 已实现部分的关键决定

1. **不另建存储**：设置界面直接读写 `sdmc:/switch/hongguo.cfg`——**和 FTP 实验开关同一个文件、同一个读取器**。
   两套存储会互相不一致，而"界面写了但 `cfgValue()` 读不到"比没有界面更糟。
2. **`cfgWrite` 的写法是"轮转 + 改名"**，不是直接覆盖：
   新内容先写 `.tmp`，旧文件改名 `.bak`，再把 `.tmp` 改名就位。
   直接覆盖在 FAT 上等于先删旧文件——控制台随时可能断电，那个窗口里会**一个设置文件都不剩**。
   逐行重建时**其它行原样保留**，所以文件自己的注释头不会被设置界面吃掉。
   重复的键会被丢弃（`cfgValue` 取第一个匹配，留下后一个会让文件与实际生效值不一致）。
3. **只列真正有效的键**。诊断那一组不是凑数：这个项目每一个悬而未决的问题都是靠翻其中一个开关、再读日志回答的，
   而每翻一次以前要重编译 + 上传 26 MB + 走到控制台。
4. **界面上写明"不做什么、为什么"**（About 页）：弹幕/评论写的是实测结论
   （`danmaku`/`comment`/`reply`/`barrage` 在载荷里出现 0 次），而不是留空让人以为漏了。
5. **按键**：borealis **没有 `BUTTON_MINUS`**（枚举只有 A/B/X/Y/START/BACK/LB/RB/LT/RT/摇杆）。
   所以 **Y = 设置**，**X 留给之后的小窗/大窗切换**——wiliwili 首页也是 Y 管搜索、X 管布局 `switch`
   （`player_base_activity.cpp:212`）。

## 二、设置存在哪里：**复用现有的 `hongguo.cfg`**

这是本项目一个现成的便宜可占。现在 `sdmc:/switch/hongguo.cfg` 已经是
`key=value` 的纯文本开关文件（`ao` / `hwdec` / `overlay` / `home.tiers` / `image.enable` / `mpv.msglevel` …），
而且我用它做过**一整轮对照实验**（改一行、重启、看日志）。

**所以设置界面不去另建一套存储**，而是：
- 设置界面**读写同一个文件**；
- 界面上每一项就是一个 key（`SettingItem` 枚举 → 字符串 key，与 wiliwili 的 `config_helper.cpp` 同名）；
- **不存在文件里的项用内置默认值**——这正是现有 `cfgValue(key, default)` 的行为。

好处是**可测**：每一项都能用 FTP 改一行验证，不需要点界面。

## 四之二、第 13 轮实际加进设置界面的行（这一节是"界面与 cfg 不许脱节"的核对表）

新增的所有 key **都进了界面**，因为一个只能靠 FTP 改的键，在界面里不存在就等于不存在。

| 标签页 | 行 | 控件 |
|---|---|---|
| Playback | Picture menu (X) / Seek style / Quality row (X) | 选择器 |
| Appearance | Home layout / Poster width / Episode picker / Episode button width / Refresh button | 选择器 + 数字输入 |
| **Network**（新标签页） | Request timeout / Connect timeout / DNS cache / Follow redirects / Verify certificate / Proxy / Image fetches at once | 数字输入 + 选择器 + 文本输入 |
| Diagnostics | Screenshot probe | 选择器 |

**数字与文本行走的是同一个校验器**：`hg_httpcfg_apply()`——也就是**启动路径用的那一个**。
于是界面**不可能接受一个应用会拒绝的值**（`timeout=0`、连接超时大于总超时、代理缺 scheme），
而且**拒绝时显示的句子与日志里的那句是同一句**。两处规则一份实现，
正是这个项目反复在避免的"同一个事实有两个来源"。

**About 页同步更新**：把"需要重启的项"从三项扩成五项（UI resolution、Home layout、
Episode picker、Network、Diagnostics），并新增一节"**立即生效**"（Player menu、seek style、
quality row、refresh button）——因为**说少了也是错**，而且是最容易让用户以为坏了的那种错。
About 页的"不做，以及为什么"也补了三条**用户会当成 bug 报告**的：缩略图画面的现状、
纹理缓存键为什么不存在、搜索接口 200+0 字节。
