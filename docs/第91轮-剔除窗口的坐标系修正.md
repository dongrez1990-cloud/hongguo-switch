# 第 91 轮：往下滚就全消失 —— 两个量不在同一个坐标系（build91）

你的两句话把根因钉死了：

> "更多界面显示到 90 还是 120 的时候，往下翻它就会全部消失了"
> "用触屏翻回来还会有显示，只要一滚动到下面就会全部消失"

**"往回翻就有、往下翻就全没"** ✓ —— 这是典型的**拿两个不同坐标系的数去比较** ✓✓。
这是我上一轮加"屏幕外不画"时引入的回归 ✗（那个改动的目的是修崩溃 ✓，方向是对的 ✓，但窗口算错了 ✓）。

---

## 一、根因（读了 borealis 的源码）

| 量 | 真实含义 |
|---|---|
| `View::getY()`（`view.cpp:1235`） | **会沿父级一路累加** ✓ 并加上 `translation` ✓ → 是**绝对屏幕坐标** ✓，内容往上滚时它**变小** ✓ |
| `ScrollingFrame::contentOffsetY`（`scrolling_frame.cpp:424-431`） | 是**正的滚动量**（被 clamp 到 `[0, contentHeight]` ✓）→ 往下滚时它**变大** ✓ |

我把这两个放进了同一个表达式 ✗ → 窗口和格子**朝相反方向移动** ✓ →
一旦不再重叠，**所有格子在同一帧被关掉** ✓✓ → 屏幕全空 ✓；往回滚时又重叠 ✓ → 于是"翻回来就有" ✓✓。

## 二、修法：两边都用绝对坐标，**不再看 `contentOffsetY`**

```cpp
const float selfTop = this->getY();          // 网格自己（视口）的绝对 y
const float selfH   = this->getHeight();
窗口 = [selfTop - selfH, selfTop + 2*selfH]  // 上下各留一屏余量
格子：bottom >= winTop && top <= winBottom 才画
```

**`contentOffsetY` 完全不参与** ✓ —— 这正是重点：**没有可以再搞反的东西了** ✓✓
（格子的绝对 y 里已经含了滚动位移 ✓）。

再加上**三道"出错就往画的一边倒"的保险** ✓：
1. 视口高度不可用 → 不剔除 ✓；
2. 格子还没有几何（刚追加、尚未布局）→ **保留** ✓（这是你看到的另一半个问题 ✓）；
3. 若这一帧会隐藏超过 **90%** 的格子 → **判定为坏数字**，整帧不剔除、全部照画 ✓，并写一行日志 ✓。

**宁可多画一帧，也不能交出一个空白屏** ✓ —— 空白屏看起来就是崩溃 ✓。
