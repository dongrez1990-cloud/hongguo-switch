## 二、这把两条崩溃路径**彻底分清**了（先前我把它们混成一条）

我原来的解释只有一条："启动时应用主题 → 视频上下文还不存在 → 空指针" ✓。但把它代进去会得到一个矛盾：
`theme=light` 早就在 cfg 里了，那么**用户按下去的那一刻之前的那次启动**就该崩 ✗ ——
可截图明明显示它**进到了设置界面** ✓。矛盾说明**还有第二条路径** ✓：

| # | 什么时候 | 崩在哪 | 为什么 |
|---|---|---|---|
| **A** | **使用中**改主题（截图里这一次，11:29） | `SwitchVideoContext::recordStaticCommands()` 里的 Data Abort | 设置行**立即**调用 `setThemeVariant`，而它会**重录 GPU 可能仍在执行**的 deko3d 静态命令列表 ✓ |
| **B** | **之后每次启动** | `Fault Address: 0x0` | cfg 里已经存了 `theme=dark`，启动时在 `createWindow` **之前**应用 → 视频上下文还不存在 → 裸解引用 ✓ |

**这条时间线解释了全部 6 份报告**：11:25/11:30（带截图）是 **A** ✓；11:30:25/34/45 与 11:32:19 是 **B** ✓
（所以"几次之后直接进去就开始闪退，进不到主页" ✓✓）。

## 三、两条都已经被修掉（`build70` / `build77`）
