## 一、"很多不显示图标" = **我的封面重试封顶造成的** ✗（已修）

我上一轮把封面重试**硬性封顶 3 次** ✗，理由是资源 ✓。但被你拒绝的封面（当时正有别的下载在跑 ✓，
被图像预算挡下 ✓）就**再也没有第二次机会**了 ✗ → 于是"更多"界面出现大量空图标 ✓（你的报告 ✓）。

**改成"退避"而不是"停手"** ✓：

```
第 1 次 400 ms → 之后每次 ×4 → 上限 10 秒
```

一分钟之后是**每分钟约 6 次**询问 ✓（而原来失控时是每分钟 150 次 ✗），
**被挡下的封面仍然会到** ✓ —— 既解决了资源问题，又不丢图标 ✓✓。

## 四、闪退的真正机制（这次证据很硬）

新崩溃报告（`01791684706`，02:11）符号化：

```
Result 0x767 (User Break)
  ← BlitCopyEngine                      ← 这是一次【图像上传】
  ← nvgEndFrame
  ← Application::frame()
```

**`BlitCopyEngine` 是图像上传** ✓ → 也就是说：**那一帧里一次性落地了多张封面纹理** ✓，
把 deko3d 的命令缓冲撑爆了 ✓✓ —— 这解释了为什么它总是发生在**封面成批到达**的时候 ✓
（主页/更多界面停留、或滚动触发新一页 ✓）。

**修法（不动任何对象的生命周期，最安全的一种）**：**给上传之间加间隔** ✓
`HG_IMAGE_INSTALL_GAP_MS = 120 ms` ✓ —— 距上次上传不足 120 ms 时**不启动新的下载** ✓，
由调用方的重试（现在是退避 ✓）稍后再来 ✓。于是一帧里最多落地**一张**封面纹理 ✓✓，
而下载本身不受影响（只是排队 ✓）。
