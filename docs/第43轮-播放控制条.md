# 第 43 轮：播放界面控制条（A 呼出）（build43）

**A1 + A2 的第一刀**（清单 A 组是最大的一件，10 个子项，这一轮先做"呼出/隐藏 + 播放暂停按钮 + 进度 + 时钟"，
其余（音量/倍速/缩放/设置面板/推荐/收藏转发）留到后续轮次，并在清单里标清）。

---

## 一、A 的行为改了（用户明确要求）

> 「点画面或按 A 呼出/隐藏（**A 从"暂停"改为"呼出控件"**）」

新行为（`player_activity.cpp`）：

| 按键 | 之前 | 现在 |
|---|---|---|
| **A** | 每次都是暂停/播放 | 控制条不在 → **呼出控制条**（播放/暂停按钮高亮）；控制条在 → **按下该按钮 = 暂停/播放** |
| B | 返回（菜单开着时先关菜单） | 不变 |
| X | 画面菜单 | 不变 |
| Y | 叠加层文字/进度开关 | 不变 |
| 左右 | 拖动定位 | 不变 |

**为什么是"两步"而不是"换了键"**：A 既要"呼出"又要能暂停，一次按键不能同时做两件事。
两步正好就是用户描述的顺序（先呼出、再作用于控件），而且**暂停永远不会变得够不着** ——
也不会让只想看控件的人误触暂停。这是这一轮唯一需要判断的地方，写在这里免得以后被当成 bug 改掉。

控制条**空闲 4 秒自动隐藏**（所有主机播放器都这样，不然画面永远被盖着），任何一次 A 都会重新计时。

## 二、画的是什么

`player_view.cpp` 新增 `drawControlBar()`，在**画面渲染之后**绘制（沿用 build37 定下的顺序规则：
叠加层必须在 `nvgUpdateImage` 之后，否则会跑到画面底下）：

```
┌──────────────────────────────────────────────────────────────┐
│ [▶/⏸]  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░       00:12 / 01:31 │
└──────────────────────────────────────────────────────────────┘
```

- **播放/暂停按钮**：48×48 圆角方块 + 主题强调色描边；播放中是**两条竖杠**（表示"按它暂停"），
  暂停时是**三角形**（表示"按它播放"）—— 用 nanovg 路径画，不依赖字体里有没有这个字形。
- **进度条**：与原来那条只读进度条**同一套两个矩形**的画法，所以"有控件"和"没控件"两种时刻看起来是同一个东西。
- **时钟**：`hg_fmt_clock(pos) / hg_fmt_clock(dur)`，与状态行同一个格式化函数，两者不可能对不上。
  位置由 `progress × duration` **推导**（不另读一次 mpv），所以它和上面那根进度条不可能互相矛盾。
- **控制条在时，替换掉原来那条独立进度条** —— 不是叠在它上面：两个进度条同屏是"新功能加在旧功能旁边"
  的典型后果。

## 三、为什么不用 brls 的按钮控件

这个界面的输入是**每帧从手柄状态轮询**的（进度条拖动、画面菜单都是这样，见 `player_view.hpp` 的说明）。
在这里放一个可聚焦的 `brls::Button` 会**给同一个界面引入第二条输入通路** —— 而本项目在别的界面上
已经为"一个界面两个移动者"付过两次代价（方向键上下做过两轮）。所以控制条是"家具"：按键仍然是按键。
**代价要写清楚**：现在只有"播放/暂停"是主按钮（A 作用于它）；要在音量/倍速/缩放之间移动选中项，
需要给控制条加一个选中索引，那是 A3–A6 的事。

## 五、请真机确认

1. 进播放页 → **按 A**：底下出现控制条（左边一个"两竖杠"按钮），**不应暂停**；
   再按一次 A → 暂停（按钮变成三角形）；再按 A → 继续播放。
2. 不动 4 秒 → 控制条自己消失（日志 `PLAYER: control bar hid itself after 4000 ms of no input`）。
3. 左右拖动定位、X 画面菜单、Y 隐藏叠加层、B 返回 —— 都应与之前一样。
4. 日志里能看到 `PLAYER: control bar up (A or a tap); it hides itself after 4000 ms [build43]`。
