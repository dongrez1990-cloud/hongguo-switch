## 一、N1：分类页翻页（实测驱动的实现）

### 1.1 实测（`app/src/tools/probe_category_paging.mjs`，现场跑的）

```
GET /category/comic-drama            -> 200, 24 条, first=7691228619774905368
GET /category/comic-drama?page=2     -> 200, 24 条, first=7691986233051843646   ← 与第一页不同
GET /category/comic-drama?page=3     -> 200, 24 条, first=7690412195565276184
GET /category/comic-drama?page=35    -> 404                                     ← 有硬终点
GET /category/comic-drama?page=34    -> 200, 但该页没有 recommendList（是末页/空页）

页对象自带：
  loaderData.category_$.pagination = { total: 800, pageNum: 1, pageSize: 24, totalPages: 34 }
```

**所以"什么时候停"不需要猜**：页面自己说了总条数与总页数（漫剧 800 部 / 34 页），
这就是这一轮的关键发现 —— 上一轮只做到"显示第一页 24 条"。

### 1.2 实现

| 层 | 改动 |
|---|---|
| `hg_api.c/h` | 新增 **`hg_api_parse_pagination()`**：从 loaderData 的页对象里读 `pagination`，**11 项主机测试**。它同时接受**数字**（分类页：`"total": 800`）与**字符串**（搜索页那种 `"totalCount": "201"`），因为"把带引号的数字读成缺失"会让"到底了"的守卫悄悄失效 |
| `hg_client` | `fetchCategory(slug, page, out, info)`：`page>1` 时加 `?page=N`（第一页用裸 URL —— 站点自己的分页链接就是从 `?page=2` 开始的），并把 `pagination` 带回 |
| `home_activity.cpp` | 网格新增 **`appendRows()`** 与 **`setOnNearBottom()`**；`setRows` 的建卡逻辑抽成 `buildRowView()`，让"重建"与"追加"不可能画得不一样；`draw()` 里新增 `tickNearBottom()`（每帧一处，400 ms 节流） |
| `category_activity.cpp` | 累积翻页：第一页 `setPosterGridRows`，之后 `appendPosterGridRows`；滚到底自动取下一页；状态栏写"显示 N 条（共 800 条）"；到底后不再请求 |
| `hg_lang` | 新增 `HG_T_LOADING`（"正在加载…"） |

**为什么必须"追加"而不是"重建"**：重建会把每个格子换成新对象，新格子没有封面、`coverSettled` 归零，
于是第 2 页会把第 1 页的 24 张封面重新下载一遍，第 3 页再把前 48 张重下一遍 —— 34 页就是几千次
请求，全为了屏幕上已经有的图。`appendRows` 只建新行，已有的格子连着封面和点击动作一起留着。

**两个停止条件**（都要，因为各有各的漏网）：`page > totalPages`（页面自己说的），
以及**某一页返回 0 条**（末页不完整 / 越界页是空页）。

**失败不清屏**：某一页失败时状态栏写原因，已经加载的页留在屏幕上，下次滚动还会重试
（`exhausted` 不动）—— 一次网络抖动不该把用户翻过的 100 部剧清空。

## 二、N4：播放画面超出电视显示范围 —— 用的是**主机自己的设置**

### 2.1 用户澄清

> 「我说的画面界面问题其实是一个：**在播放界面时，主机模式下会超出电视显示范围**」

所以不是整个界面、也不是别的屏幕：**只有播放画面**。原因也很自然 —— 这个 App 里**只有播放画面是
贴边全幅**的，其它每个界面都有 24 px 内边距，所以电视的过扫描（overscan）只把播放画面啃掉。

### 2.2 正解：`setsysGetTvSettings().underscan`

主机设置里"电视机画面尺寸 100% / 95% / 90%"这个值，libnx 是能读到的：

```c
// set.h:417-426
typedef struct { u32 flags; s32 tv_resolution; s32 hdmi_content_type; s32 rgb_range;
                 s32 cmu_mode; u32 underscan; float gamma; float contrast; } SetSysTvSettings;
Result setsysGetTvSettings(SetSysTvSettings *out);
```

**这不是猜一个边距，而是问主机自己**。新建 `app/hongguo/hg_tv.hpp/.cpp`：

- `tvSafePercent()`：读 `underscan`，按主机自己的三档映射 **0→100% / 1→95% / 2→90%**；
- `tvIsDocked()`：`appletGetOperationMode() == Console` —— 安全区是电视概念，
  掌机模式**不做任何内缩**（那会对着一块没有过扫描的屏幕缩小画面）；
- `tvApplySafeArea(&x,&y,&w,&h)`：**居中内缩**，宽高一起缩（是"画小一点"，不是"裁一块"）；
- 全部走 `player.tv.safe=<百分比>` 的 cfg 覆盖（50..100），这是映射万一不对时的退路 —— 一条 FTP，不用重构建。

### 2.3 两条诚实说明（都让日志负责，不靠静默）

1. libnx 对 `underscan` **只写了"Underscan"，没有给枚举值**。所以原始值**打进日志**：
   映射错了会在日志里露出来，而不是悄悄按 0 处理。
2. 值不在 0..2 时**当成 100%（不内缩）并专门记一行**：按一个看不懂的值缩小画面，
   是没人能解释的行为。

日志（每次运行一条）：

```
TV: docked=1 underscan=1 -> safe=95% (override=0) [build41]
```

解析流程也交代清楚：`setsysInitialize()` 在本 App **别处没人调用**（app/ 与 borealis 的 switch 平台都查过），
所以由 `hg_tv.cpp` 读一次、读完立刻 `setsysExit()`；失败就退回 100% 并在日志里说明。

### 2.4 施加位置

只改 `player_view.cpp` 里软件渲染的**视频矩形**（`nvgRect` 与 `nvgImagePattern` 用同一组坐标 ——
这是 build37 定下的规矩：两者必须一致，否则是裁切而不是缩放）。界面文字不动。

## 四、请真机确认

1. **分类页往下刷**：主页某一栏按"更多"进分类页 → 一直往下滚，网格会**继续加载**（状态栏从
   "显示 24 条（共 800 条）"往上涨）；日志有 `CATEGORY: page 2 showed 24 series (48 loaded so far, 34 pages total)`。
   **已有的封面不应重新下载**（日志里不应再出现同一批 `IMG: fetching`）。
2. **主机模式播放**：插电视 → 播一集 → 画面应当**完整落在电视可视范围内**（不再被电视边裁掉）。
   日志里有 `TV: docked=1 underscan=? -> safe=?%`，**把这个数字给我**：
   - 如果是 `underscan=1 -> safe=95%` 且画面正常 → 说明主机的电视画面尺寸设的是 95% ✓ 收工；
   - 如果 `underscan=0 -> safe=100%` 但**画面仍超出** → 说明不是过扫描，我在 `hongguo.cfg` 里加
     `player.tv.safe=95` 先验证是不是这个方向（这条我这一轮已经实现，不用重构建）。
3. **回归**：主页 `/search` 结果网格、方向键、返回都不受影响（分类页与搜索页共用同一个网格）。
