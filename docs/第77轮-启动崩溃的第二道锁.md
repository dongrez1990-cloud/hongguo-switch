# 第 77 轮：把最严重那条修复从"靠顺序"变成"结构上不可能再犯"（build77）

真机仍停在 `build69`（日志没变）。这一轮做的是**给最严重的那条 bug 加第二道锁**。

---

## 一、为什么还要动它

`build70` 修掉了"启动必崩"：主题原来在 `createWindow` **之前**应用，而 borealis 的
`setThemeVariant()` **无条件**解引用视频上下文（那时还是 null）→ `Fault Address 0x0` ✓。
修法是把应用挪到 `createWindow` 之后 ✓ —— **顺序对了，风险还在**：

- 这是"**靠调用位置正确**"的修复 ✗ —— 下一个动这几行的人（或者下一个我）就可能把它挪回去，
  而症状是"应用**完全无法启动**"，代价极大；
- 而且这条链上**没有任何一层能优雅失败**：框架里那句是裸解引用 ✓。

## 二、这一轮加的第二道锁

`Platform::getVideoContext()` 是公开的（`platform.hpp:215` ✓），所以可以**先问再调**：

```cpp
if (platform && wanted && platform->getVideoContext() == nullptr) {
    logPrintf("boot: theme='%s' NOT applied [build77] -- the video context does not exist yet, and borealis' "
              "setThemeVariant() dereferences it unconditionally (this is the crash from build69). "
              "The console's own theme is used for this session.");
} else if (platform && wanted) {
    platform->setThemeVariant(...);
}
```

于是这条失败路径变成了**一行日志 + 这次主题没变**（可恢复、可见 ✓），
而不是**应用打不开**（不可恢复、只有崩溃报告 ✓）。

**核实过的两件事**（不是推测）：
1. 应用点确实在 `createWindow` **之后**：`hg_boot.cpp` 里 `createWindow` 在第 209 行、主题应用在第 220 行 ✓；
2. `getVideoContext()` 是 `brls::Platform` 的**公开纯虚**接口 ✓（上游 `switch_platform.cpp:59` 自己就是这么用的 ✓）。
