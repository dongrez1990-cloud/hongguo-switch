# 第 2 步：首页网格排版（home.layout）

交接文档 §二 的第 2 步。**代码已完成、已构建已部署、未上机。**

---

## 一、做了什么

首页从「一个卡片占一行」的竖排列表，改成 **wiliwili 那样的海报网格**：

- **列数不是写死的**。按逻辑宽度和 `home.cellW`（默认 200）算出来：

  | `ui.scale` | 逻辑宽度 | 列数 |
  |---|---|---|
  | 544p | 960×544 | 4 |
  | 720p（默认） | 1280×720 | 6 |
  | 900p | 1600×900 | 7 |
  | 1080p | 1920×1080 | 8 |

- **分区标题仍然保留**，作为整行宽的标题条，并把列游标**归零**——所以每个分区的卡片都从第 0 列开始，不会接在上一区末尾那一列后面。
- 卡片 = **竖版海报**（2:3）+ 集数角标（`episode_cnt`，36/36 覆盖）+ 两行标题。
- 方向键按阅读顺序移动，靠 borealis 自己的焦点遍历，没有一行自写导航。

## 二、关于「搬 wiliwili 的 RecyclingGrid」这一步的诚实交代

交接文档的原话是「**搬 `RecyclingGrid`**（borealis 的 `RecyclerFrame` 没有网格能力）」。
**网格能力这一条是对的，但整份搬进来是错的选择**，理由是可验证的：

`recycling_grid.hpp` 267 行、`recycling_grid.cpp` 29 KB，它把三件事混在一起：

| 它包含 | 这个项目需要吗 |
|---|---|
| **布局**（列数、格子宽、间距） | **要**——但算术可以单独抽出来测 |
| **回收**（cell pool、可见窗口、预取） | **不要**（见下） |
| **滚动与焦点导航**（`getNextFocus`、`selectRowAt`、`getNextCellFocus`） | **不要**——`brls::ScrollingFrame` 已经会滚动到焦点，`Box::getNextFocus` 已经按子节点顺序走（`box.cpp:409-443`） |

所以实际做法是：**抄它的布局模型，不抄它的滚动/焦点**，并且把布局算术放进 C 层
（`hg_grid.c`，55 项主机测试）。好处是这套网格继承 borealis 在滚动/焦点上的行为，
而不是立第二套实现等着跟它不一致。

**为什么不做 cell 回收**：wiliwili 的网格是为无限流做的；这一页是 **36 卡 + 4 标题，一次全部已知**。
一个卡片贵的部分是**封面下载**，不是那个 Box——而回收恰恰会跟它打架：
被回收的格子必须重新取图，于是上下滚动会重启下载。
40 个格子各自留着封面，既更简单也更省事。日志里打了格子数，
将来若真要几百张卡的页面，这里有据可依。

> **这正是「必须偏离的一处」的兑现**：wiliwili 缩略图是 16:9 横版，红果封面是竖版海报。
> **网格结构照抄，比例改成海报的**（`cellH = cellW * 3/2 + 文字区`）。

## 三、四个关键决定

### 1. 两个布局并存，网格是默认，列表是退路

首页是「当前唯一已经能用」的屏幕之一，改动它必须带一条**不用重编译**的回路。
`home.layout=list` 就是那条路——回到一行一卡的老界面，那正是真机验证过的形状。

### 2. 行模型只有一份，两种布局共用

`hg_api_home_rows()`（已在主机测试里）给出「标题行 + 该区卡片」的行序列，
**两种布局都消费它**；网格再用 `hg_grid_layout()` 把它变成列坐标。
两边都不重新推导页面形状，所以两边的索引不会各自漂移。

### 3. 布局算术在 C 层

第三个「静默失败」的算术：列索引错一位只是卡片挪一格，看起来仍然像网格；
总高度少算一行只是**最后一行被裁掉**，而「有些卡不见了」不会让人想到高度算术。
`hg_grid_test.c` 55 项检查覆盖列数、行不重叠、总高度覆盖最后一行、标题归零列、
以及退化情形（0 项 / 缓冲不够 / 宽度不可用）。

写这个套件时**真的抓到一个 bug**：`cellW <= 1` 的阈值太松，
100 宽内容 + 90 间距会产出 5 像素宽的格子。已改成 `HG_GRID_MIN_CELL_W = 64`。

### 4. `Label` 没有 `setPadding`，角标必须用 Box 包

`views/label.hpp:60-193` 只有字号、颜色、对齐，**没有 padding**。
所以集数角标的深色底板是一个 `Box`（顺带让底板贴合文字，而不是撑满整格宽度）——
这跟前一版「`brls::Slider` 不能用在播放页」是同一类事实：**先查 API，别照直觉写**。

## 四、退路（不用重编译）

| 退路 | 效果 |
|---|---|
| `home.layout=list` | 回到一行一卡的老列表（真机验证过的形状） |
| `home.tiers=no` | 去掉分区标题，得到扁平网格（与上面正交，可组合） |
| `home.cellW=150` | 海报变小、每行更多 |

## 五、观察点

**屏幕**：首页出现多列海报，每张下面两行标题，右上角集数角标；
分区标题占整行且每个分区都从最左边开始；方向键左右上下按位置移动。

**日志**：

```
HOME: layout = GRID (cfg home.layout; grid is the default, list is the way back)
HOME: grid view built (home.layout=grid, ui logical width decides columns)
HOMEGRID: built 40 items (36 cards, 4 headings)
HOMEGRID: layout #1 w=1232 -> 6 columns, cell 189.3x340.0, contentH=1568 (36 cards, 4 headings)
HOME apply: grid populated (36 cards, 6 columns), focus given to the grid
```

判读：

| 现象 | 结论 |
|---|---|
| `layout = LIST` | cfg 里写了 `home.layout=list` |
| `layout placed N of 40 -- NOT showing a partial grid` | 布局被拒（宽度不可用或格子过窄），屏幕会空——**这条日志就是为了不把这种情况当成"没数据"** |
| 有 `built` 但没有 `layout #` | 帧从未拿到有效宽度 → 查 `ui.scale` |
| 列数与 §一 的表不符 | `home.cellW` 被改过 |
| 卡片贴在一起/重叠 | 间距常量或 `hg_grid_layout` 的调用参数变了 |

**必需真机确认的一点**：`ScrollingFrame` 是否按绝对定位的单元格正确滚动到焦点。
这是这套实现里**唯一没有主机测试覆盖**的部分（它属于 borealis 的行为），
如果滚动不到或焦点跑丢，`home.layout=list` 一条线即可回避。
