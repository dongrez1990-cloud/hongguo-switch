# 第 48 轮：换集 / 播完自动下一集 / 播放方式（build48）

**F1 + F2 + A8 的"播放方式"** —— 这三件是同一件事的三面：有换集才有"播完去哪"，有"播完去哪"才谈得上播放方式。

---

## 一、F2 其实**早就满足了**（实测，不是推断）

交接文档 F2 写的是"L / R = 快进 / 快退"。查 borealis 自己的 Switch 后端：

```
switch_input.cpp:27   HidNpadButton_L  -> BUTTON_LB
switch_input.cpp:26   HidNpadButton_ZL -> BUTTON_LT
switch_input.cpp:48   HidNpadButton_ZR -> BUTTON_RT
```

**抽象名 `LB` 就是手柄上的 L**，Switch 没有独立的"肩键+L"两个键。所以播放器里那条 LB/RB 粗定位
**已经就是 L/R 快进快退** ✓ —— 我一开始按字面加了 `BUTTON_L`/`BUTTON_R`（**根本不存在**，编译不过），
撤掉并在原处写清楚映射关系。

**顺带一个必须记住的命名坑**：**ZL/ZR 在 borealis 里叫 `BUTTON_LT`/`BUTTON_RT`**（Xbox 风格的名字）。
写 `BUTTON_ZL` 编译不过，而"猜它存在"会白费一轮。

## 二、F1：ZL/ZR 上一集 / 下一集

- 播放器现在拿到**整份剧集列表**（不是只有一个 episodeId）：详情页本来就有这份列表，传引用式拷贝几毫秒，
  **省掉一次详情页请求**，也保证两个界面对"下一集是哪个"不会各说各话。
- ZL/ZR 是**注册动作**（一次按键一步，borealis 自带的重复正合适）；拖动定位仍是轮询（需要加速度），
  两条路径不重叠。
- **到两端拒绝而不是回绕**：剧集列表不是环。从最后一集跳回第一集看起来就是 bug，
  用户多按一次 ZR 会莫名回到第 1 集且无从判断。拒绝会记日志。
- 换集后**叠加上显示"第 N 集"** —— 没有它，自动换集看起来像画面抽了一下。

## 三、播完自动下一集 + 播放方式（A8 的第三行）

- `MPV_EVENT_END_FILE` 以前**只打日志**（实测确认），现在：**只有 `MPV_END_FILE_REASON_EOF`** 才触发
  "这一集演完了"。**STOP 不算** —— 拖动、显式停止都会报 STOP，把它当成"演完"会在任何一次打断时自动跳集，
  正是这个项目反复遇到的那类 bug。
- 决定权交给**活动**（它才知道剧集列表）；视图只负责上报。
  事件排空函数是从**两个线程**调的（轮询线程 + draw），所以它拿不到 `this` ——
  改为在 `Impl` 里存一个 `owner`（构造时赋值一次），而不是给两个调用点各传一遍指针
  （那样有一边只能传 nullptr，恰好在最可能看到 EOF 的地方丢掉回调）。
- 设置面板新增第三行 **播放方式：停在结尾 / 自动下一集**，**默认"停在结尾"**（= 这个功能存在之前的行为，
  新行为要求用户主动打开）。

## 五、请真机确认

1. 播放中按 **ZL / ZR** → 上一集 / 下一集（日志 `PLAYER: ZR pressed -> next episode`、
   `PLAYER: next episode -> episode 4`）；**在第一集按 ZL、最后一集按 ZR 应什么都不发生**（有日志说明）。
2. 按 A → 上/下移到 **设置** → A → 面板第三行 **播放方式** → 左右改成 **自动下一集**。
   然后让一集**自然演完** → 应自动进入下一集，叠加层显示"第 N 集"。
   改回"停在结尾" → 演完就停在结尾（不再自动跳）。
3. 拖动定位中途松手（会报 STOP）**不应**触发自动跳集。
