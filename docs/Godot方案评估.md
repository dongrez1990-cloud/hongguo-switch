# 用 Godot 重做界面可行吗：实测评估与结论

**问的问题**：「结合现有的打通的部分，直接用 Godot 做 UI 会不会更简单？」
以及「新开一个会话用 godot 把它变成 wiliwili 界面，实现类似于 wiliwili 的各种功能，
只是链接和视频是红果的」。

**结论：现在不做。** 下面是查到的依据和理由，**包括支持 Godot 的那部分**。

> **补充（2026-10-09，用户提出的决定性理由且已采纳）**：Godot 3.5 的 Switch 移植
> **没有蓝牙音频支持**。主机上蓝牙耳机是最常用的听音方式，切过去就意味着**蓝牙耳机没声音**。
> 这条是"功能缺失"而不是"好不好写"，**所以结论是明确的"不做"**，见 §四之二。

---

## 一、先说查到的硬事实（这才是决定性的）

| 事实 | 来源 |
|---|---|
| Godot **4** 的 Switch devkitPro 移植是一个**未合并的 PR**（#88747），**不在任何发行版里** | [godotengine/godot PR #88747](https://github.com/godotengine/godot/pull/88747) |
| Godot **3.5** 有社区 homebrew 移植，由个人维护 | [godot_switch](https://raw.githubusercontent.com/redthing1/godot_switch/refs/heads/3.5-stable_switch/README.md)、[godot-nx](https://github.com/PuntoScene/godot-nx) |
| **官方**主机支持需要走任天堂**授权**渠道（发行商协议），不是下载一个模板 | [Godot 官方文档](https://docs.godotengine.org/cs/4.x/tutorials/platform/consoles.html#console-publishing-process) |

**也就是说：如果切到 Godot，落点不是"Godot 4 + 官方 Switch 支持"，
而是"Godot 3.5 + 个人维护的非官方移植"。** 这是拿一个**已经在你主机上跑起来**的应用
去换一个**能不能编译出来都还不确定**的路线。

### 本机环境的实测结果（刚刚查的）

```
C:\devkitPro 下没有任何 godot 相关文件
C:\devkitPro\portlibs\switch\lib 下没有 libgodot
从这台机器直连 github.com 失败（TLS 连接被切断）
```

**所以"在这个环境里产出一个 Godot 的 Switch NRO"这件事，我现在无法验证。**
而 `web_search` 能用不等于能下载源码或预编译包 —— 拿不到树就没法试。

**这一条我是当作"未知"报的，不是当作"不行"。** 但它足以让"新开会话去做"变成
一个**前提未验证**的计划。

## 二、"现有的打通的部分"到底值多少 —— 这是最关键的账

下面这些**已经在你的主机上验证过**：

| 已有的东西 | 位置 | 换到 Godot 会怎样 |
|---|---|---|
| 接口逆向（签名/加密的自定义 header、加载器协议） | `hg_api` / `hg_sign` / `hg_medusa` | **不能带过去**：C 代码，直连 libcurl |
| **CENC 解密**（视频流是加密的） | `hg_cenc` / `hg_mp4` / `hg_aesv3` | **不能带过去**，只能重写 |
| 播放器（mpv + deko3d + 软件渲染两条路） | `player_view.cpp` | **不能带过去**：`VideoStreamPlayer` 播不了 DASH+CENC |
| 网格/选集/画面菜单/拖动进度/清晰度档 | 已验证渲染正常 | 界面部分可以重做，**但这是最容易的部分** |

**换算过来就是**：Godot 能接手的恰恰是**已经做完、且风险最低**的那一层；
它接不了的是**最贵、最难、且已经验证可用**的那一层（加密流 + 播放器）。

**而且它会把项目里最大的杠杆拿走**：现在有 **wiliwili 的完整源码**可以照抄
（侧边栏结构、逐屏按键表、播放设置分组、触摸语义）—— 那是一个做过同样事情的、
经过验证的实现。用 Godot 之后，**这个参照物就没了**，因为 wiliwili 不是 Godot 写的。

---

## 三、公平地说，Godot 确实会解决什么

你的直觉里有一条是对的，而且要承认：

| 问题 | Godot 会怎样 |
|---|---|
| 布局（侧边栏/网格/面板） | **明显更好写**。borealis 的手工坐标 + Yoga 混用是这两轮 bug 的来源之一 |
| **中文与 UTF-8** | **彻底消失**。这个项目已经为 GBK/936 撕过三次源码（注释里的中文、字符串里的中文、全角括号），Godot 资源是 UTF-8 的，这一整类问题不存在 |
| 迭代布局 | 不用每次走主机往返 |

**但也要注意上一轮真正出问题的是什么**：D-Pad 方向错是**一行**（`Axis::COLUMN` 应为 `ROW`），
崩溃是**我自己加的预算上限**。**两个都不是框架限制。**

## 四、结论与可选路径

### 现在不做的理由（按重要性）

1. **Godot 4 的 Switch 目标还不存在**（PR 未合并）；3.5 是个人维护的非官方移植
2. 数据层 + 播放器是 C++，**带不走** —— 那是这个项目最贵的部分
3. 界面**已经在你的主机上工作了**（截图为证：网格、选集、画面菜单、清晰度档都渲染正常）
4. 手上有 **wiliwili 源码**这个参照物，切走就失去它
5. **本机无法验证能否编出 Godot 的 Switch 二进制**（环境里没有 Godot，github 连不上）

### 如果还想探索，成本最低的一条路

**先花一小时验证平台，再谈重写**：

1. 在一个**有网络、能访问 github** 的环境里，试着编出 **Godot 3.5 的 homebrew NRO**
   （只需一个空场景 + 一行中文标签 + 一个网格）；
2. 放到主机上跑。**能跑起来**，才说明这条路线存在；**跑不起来**，讨论就结束了，
   而且代价是一小时而不是几个月；
3. 只有第 2 步成功之后，才值得讨论"重写"和"怎么把 CENC 那层搬过去"。

**在验证通过之前，我不会新开会话去做重写** —— 那等于把"能不能编译出来"这个前提
当成已知，而它恰恰是唯一没验证的东西。

### 如果验证通过了，架构必须这样分（预先说明，免得重蹈覆辙）

- **Godot 只做界面**（场景、布局、动画、触屏手势）
- **数据层与播放用 GDExtension（C++）**，而不是 GDScript 重写：
  CENC/签名/DASH 直接复用现有的 C 代码，mpv 作为原生库链进来
- 也就是说：**Godot 接手的是"画界面"，不是"实现功能"** —— 这也是它唯一比 borealis 强的地方

## 四之二、**用户提出的决定性理由：Godot 3.5 没有蓝牙音频**

**这是最终拍板的那一条，而且比上面所有理由都更实在**：

> 「我想起来 3.5 godot 的没有蓝牙音频还是不行」

主机上蓝牙耳机是最常用的听音方式。**Godot 3.5 的 Switch homebrew 移植没有蓝牙音频支持**，
意味着一旦切过去，**用蓝牙耳机就没有声音** —— 这不是"界面好不好写"的问题，
而是**功能直接缺失**。

**所以结论从"不推荐"变成"不做"**，依据是这一条加上 §一 的版本事实。
记录在这里是为了：**下次再有人提"要不要换引擎"，先看这一条。**
