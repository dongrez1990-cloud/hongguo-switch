# 第 3 步：详情页补全（简介 + 选集网格）

交接文档 §二 的第 3 步。**代码已完成、已构建已部署、未上机。**

## 一、做了什么

1. **简介**：详情页标题下方多一段可换行的简介。
   - **数据是真的不可靠**：`desc`（`series_intro`）**时有时无**——一份捕获 0/36，
     另一份只有 2 张超 500 字节；而 `tags`（`category_list`）**36/36 覆盖**。
   - 所以：**有简介就显示简介，没有就用 tags 顶替，两个都没有就整块隐藏**。
     空着的有边框盒子看起来像"加载失败"，比不显示更糟。日志会说用了哪个来源。

2. **选集从 76 行列表改成编号按钮网格**：
   - 76 行只为「数字」滚动实在太多；wiliwili 的详情页也是网格。
   - 默认 720p 下 **8 列 × 10 行**（76 集），整个选集区高度 668 逻辑像素。
   - 按钮上只画编号，**集号 id 写进日志**——按钮显示 "N" 而 N 对错 id 正是那种静默失败。

## 二、为了做这一步，`hg_grid` 的形状变成了参数

首页的海报是 **2:3 竖版**，选集按钮是 **一个数字 + 内边距**。把一种形状强加给两边，
要么让按钮变成 340 像素高，要么把海报压扁。所以格子形状变成了入参：

```c
typedef struct {
  float aspectNum;   /* 0 = 没有图，整个格子就是 extraH 高 */
  float aspectDen;
  float extraH;      /* 图下面的高度：海报是两行标题，按钮就是它的框 */
} HgGridMetrics;
```

`aspectNum = 0`（而不是 1）是刻意的：**1 会被读成"正方形"**，而一个忘了设这个字段的调用者
应该得到一个正方形格子，不是一个零高度的格子。

**一个 C/C++ 的差别在这里咬了一口**：`HG_GRID_POSTER_METRICS` 定义成 C 的复合字面量，
在 C 里是对象、在 **C++ 里是临时量**——`&HG_GRID_POSTER_METRICS` 于是报
`taking address of rvalue`。所以 C++ 侧用了具名的 `static const HgGridMetrics`，
而测试里专门有一条检查**宏与具名常量数值一致**，两边不会悄悄漂移。

## 四、观察点

**屏幕**：详情页标题下有简介（或类型标签）；下面是编号按钮网格，方向键按位置移动，
按 A 播放对应集。

**日志**：

```
DETAIL: episode layout = GRID (cfg detail.episodes; grid is the default, list is the way back)
DETAIL: synopsis from series_intro (312 bytes)     或  from tags (desc was empty)
DETAIL: ENTER createContentView; empty episode GRID attached
EPGRID: built 76 episode buttons
EPGRID: layout #1 w=1232 -> 8 columns, button 143.5x56.0, contentH=668 (76 episodes)
DETAIL apply: grid populated (76 buttons, 8 columns), focus given to it
EPGRID: episode 7 selected, id=<episode id>
```

判读：

| 现象 | 结论 |
|---|---|
| `no synopsis and no tags upstream -- the block is hidden` | 上游这次两个字段都空，**不是 bug** |
| `from tags (desc was empty)` | 简介缺失时的预期行为 |
| `EPGRID: layout placed N of 76 -- NOT showing a partial picker` | 布局被拒（宽度不可用/格子太窄），屏幕会空 |
| 列数不是 8 | `detail.cellW` 被改过，或 `ui.scale` 不是 720p |
| 按 A 不播放 | 看有没有 `episode N selected` 那一行——**有就是播放器的问题，没有就是按键没到格子** |
