# 第 90 轮：闪退的根因（一帧画了 144 个格子）与选集延迟（build90）

你这次报告了两件事，而它们**是同一个根因** ✓✓：

> "选视频界面延迟可以低一点吗？加载的有点慢，倒是没有闪退了"
> "刚才又遇到一次在选集界面，看了几秒钟视频，然后退出来，再想退出到主页的时候闪退了"

—— "没有闪退了"是**上传节流**起了作用 ✓（那条修对了 ✓）；而**新的这次崩溃**和**延迟**一起指向了同一件事 ✓。

## 一、证据：崩溃报告 + 同一份日志

崩溃报告（`01791693604`，04:40）符号化：

```
Result 0x767 (User Break)
  dk::detail::RaiseError -> CmdBuf::requestCmdMem      ← deko3d 命令内存耗尽
    <- CmdBufWriter::reserve
    <- CmdBuf::draw  <- nvgEndFrame  <- Application::frame()
```

而同一次会话的日志里：

```
HOMEGRID: appended 24 rows (now 144 items, 144 cards)
```

**144 个格子，而每一个都在画** ✗ —— 包括**屏幕外**几百像素处的那些 ✓。
一个卡片 = 圆角矩形 + 封面图 + 文字（有时还有标题条）✓ → **144 个就是每帧几百条 nanovg 命令** ✓✓
→ 命令缓冲被撑爆 ✓✓。**这也正是"延迟"的来源**：每帧都在为看不见的卡片做同样的工作 ✗。

你说"退出到主页时崩" ✓ 也对得上：回到主页的那一帧要**重建并绘制整个网格** ✓，
而命令缓冲里还压着播放器留下的东西 ✓ → 于是正好在那一帧溢出 ✓。

## 二、修法：屏幕外的格子**不画**（保留位置）

```
只画：可见区域 + 上下各一整屏的余量
例外：当前聚焦的那个格子永远画（否则光标无法移动到屏幕外的格子 ✓）
```

用 `INVISIBLE` 而不是 `GONE` ✓ —— **这是关键细节**：`GONE` 会把格子从布局里拿掉 ✗，
而这个网格的坐标是 `hg_grid_layout`（有主机测试 ✓）算好的绝对位置 ✓ → **几何绝不能动** ✓；
`INVISIBLE` 保留矩形、只跳过绘制 ✓ 正是要的那一半 ✓。

日志会说明效果 ✓：`HOMEGRID cull: 96 of 144 cells are outside the drawn window …` ✓ ——
也就是说**每帧只画大约 48 个** ✓（余量内含 ✓），命令量降到三分之一以下 ✓✓。
