# 第 2 步补完：首页小窗/大窗切换（X）

第 2 步剩下的一半。**代码已完成、已构建已部署、未上机。**

---

## 一、做了什么

首页按 **X** 在**大格子 / 小格子**之间切换（wiliwili 自己的布局切换就在 X 上，
`player_base_activity.cpp:212`，所以保持同一个键做同一件事）。

| `ui.scale` | 大格子 | 小格子 |
|---|---|---|
| 544p | 4 列 | 8 列 |
| 720p | 6 列 | **11 列** |
| 900p | 7 列 | 12 列 |
| 1080p | 8 列 | 12 列 |

小格子的目标宽度是 `home.cellW` 的 **55%**（派生而非第二个 cfg 键：调过大格子尺寸的人
不该还要记得一个只在开关打开时才起作用的数字）。

**小格子还会在标题下面显示类型标签（tags）**——所以这个切换不只是"更多列"，
而是**更多卡片 + 每张更少细节**，这正是"小窗"该有的取舍。
（`tags` 36/36 覆盖，而 `desc` 一份捕获里 0/36——见交接文档 §三。）

**切换时什么都不重新取、没有一个视图被重建**：同一批 cell 换到新坐标。
这是它便宜到能放在按键上的原因，也是用户已经看到的封面不会被按新密度重新下载的原因。

## 二、这一轮主机测试抓到的**第三个**静默 bug（而且是最隐蔽的一个）

第一版把紧凑目标定在 **68%**（136 pt），而且用**默认的 8 列上限**。实测：

```
544p   large=4  68%(136)=6         <- 只有这里"变了"
720p   large=6  68%(136)=8         <- 上限截断，本来算出来是 8
900p   large=7  68%(136)=8         <- 上限截断，本来算出来是 10
1080p  large=8  68%(136)=8         <- 上限截断，本来算出来是 12
```

**列上限被硬编码成 8**，所以 `maxColumns` 大于 8 的请求被降到 8。
在 720p 及以上，这个切换**只把海报变小、列数一点没变**——
一个"看起来生效了"的按键。**这是最糟的一类坏**：它没有报错、没有空白、没有异常，
只是没做它该做的事，而用户只会觉得"这个键有点怪"。

两处修改：

1. `HG_GRID_MAX_COLUMNS` 仍是**默认**上限 8，但新增 `HG_GRID_MAX_COLUMNS_HARD = 12`
   作为**允许调用方请求的上限**——`maxColumns` 现在被夹到 hard 上限而不是默认上限。
2. 紧凑比例从 68% 降到 **55%**。

结果就是上表：**四种分辨率下小格子都严格比大格子列数多**。

而且这次的测试**断言的是关系，不是数字**：

```c
for (每个 ui.scale) {
  big   = hg_grid_columns_for(w, 200, 0);
  small = hg_grid_columns_for(w, 110, 12);
  if (small <= big) allDenser = 0;
}
ok("compact has MORE columns than large at every ui.scale", allDenser);
```

这条检查会在**任何**未来把其中一个常数改回去的改动上失败。逐个数字的检查也在，
但**关系**才是这个 bug 的本质：不是"数值错了"，而是"两个布局算出来一样"。

## 三、退路

| 退路 | 效果 |
|---|---|
| `home.layout=list` | 整个网格（连同这个切换）换回列表 |
| 不按 X | 大格子，即原来验证过的观感 |

网格存在时没有为这个切换单独加开关：它只改一个数字、重跑一个
**本项目在主机上测过的**纯算术函数，没有别的东西可以坏。

## 四、观察点

**屏幕**：首页按 X → 海报变小、每行卡片变多、标题下多出一行类型标签；
再按一次回去。焦点**停在原来那张卡上**（只是换了位置）。

**日志**：

```
HOME: X pressed -> toggle cell size
HOMEGRID: X -> SMALL cells
HOMEGRID: layout #2 w=1232 COMPACT -> 11 columns, cell 97.1x201.6, contentH=... (36 cards, 4 headings, focus was item 7)
HOME: X pressed -> toggle cell size
HOMEGRID: X -> LARGE cells
HOMEGRID: layout #3 w=1232 large -> 6 columns, cell 189.3x340.0, ... (focus was item 7)
```

判读：

| 现象 | 结论 |
|---|---|
| `X pressed` 之后**没有** `HOMEGRID: X ->` | 动作没触发——查 `X registered` 那行（X 注册在**网格**上，靠焦点向上查找命中） |
| `-> SMALL cells` 但列数和大格子一样 | **就是上面那个 bug 回来了**；`hg_grid_test` 的关系检查应该先失败 |
| `focus was item -1` | 按 X 时焦点不在卡片上（可能在标题上），不是错误，但仍会给出焦点 |
| 布局出现但卡片瞬间全变灰 | 不该发生：切换不重建视图。发生了就说明走的是重建路径 |
